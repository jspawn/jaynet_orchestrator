# v1.20.8 — run() refactor phases 1–2 + first guard ablation

Minor release on 1.20.7. The audit #1 loop refactor starts (no behavior
change intended), the first guard ablation lands a real fix, and two
growth-discipline gates join CI. No config migration.

## Dispatch gates become a pipeline

The 16 inline pre-exec tool-call checks in `AgentRuntime.run` moved to
`runtime/dispatch_guards.py` as the `DISPATCH_GATES` pipeline —
`DispatchGate` classes over a shared `DispatchGateContext`, in exact
historical inline order (load-bearing: traces, hint order, UI). Security
gates (admin-only, allowlist, privacy, confirmation) are marked
non-ablatable so `guards_off` experiments can never strip them. Phase 2
added `SpawnService` and extracted final-answer application; `run()`
drops from ~2,550 to ~1,900 lines.

## First guard ablation → stall-ladder fix

70.7% guards-ON vs 67.2% guards-OFF (docs/brain-bakeoff.md). The
ablation's real catch: the stall ladder's rung-3 "produce NOW" pressure
was derailing research runs that pass when left alone
(gaia-46719c30 / d0633230 / dc22a632). Fix: a turn of only fresh
web/arxiv/browser calls (all ok, no identical-args repeat) is now
ladder-neutral — reading fresh pages IS the work. Identical re-fetches
and failed fetches still escalate; the near-dup guard is untouched.
verify_arm, the initial suspect, injects no text — telemetry bystander.
