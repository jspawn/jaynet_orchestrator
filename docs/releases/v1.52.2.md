# JayNet v1.52.2 — loop correctness and faster run setup

This patch fixes the verified loop findings and applies the two useful,
low-risk performance suggestions.

## Correctness and privacy

- Interactive TTY confirmations emit `via: "tty"` instead of raising
  `UnboundLocalError` after the user's answer.
- Admin `force_tools` works with the default `disabled_tools=None`.
- `tools.load` schema rebuilds preserve brain-gate routing/rejection notes.
- Independently cancelled parallel tool children propagate `CancelledError`
  instead of turning it into an ordinary tool error and starting another turn.
- Dynamic `result.private=True` survives `_execute_tool`; private image messages
  are indexed in the run's privacy taint as well.
- Plugin route telemetry keeps the hook's tag when keyword notes take over.
- Dotted admin overrides replace YAML null/scalar intermediate values instead
  of crashing during boot.

## Consistent run-local configuration

Role policy, brain-gate activation and schema notes, system-prompt slot data,
routing helpers, cloud/privacy confirmation, spawned-run confirmation and tool
timeouts now consume the same run-local configuration as tool execution. This
covers `tools_patch` and internal `config_patch` without mutating shared runtime
configuration or weakening the isolation between concurrent runs.

## Performance

- The default specialist and three named-specialist health probes now run
  concurrently. Each retains its own failure fallback, and cancellation still
  propagates normally.
- Per-run tools patches shallow-copy the tools section and deep-copy only the
  patched namespaces. Unpatched namespaces remain shared read-only views.

The registry-name caching suggestion was deliberately skipped: its overhead is
small and a cache would require careful invalidation after plugin hot-reloads.

## Verification

2,919 tests pass, including concurrency, cancellation, dynamic-privacy,
run-local config and copy-isolation regressions. Ruff, mypy, complexity, prompt
budgets, generated docs/rails, dependency audits, ShellCheck and diff hygiene
pass.

## Upgrading from v1.52.1

No dependency or database migration is required:

```bash
git fetch --tags
git checkout v1.52.2
systemctl --user restart jaynet-web
scripts/orch --doctor
```
