# JayNet v1.40.0 — multi-backend presets

JayNet can now *launch* vLLM and radiance servers itself, not just adopt
them — presets are typed per backend and translated at launch.

## Backend-typed presets

- A preset's `.conf` is canonical per backend; `runtime/launch_argv.py`
  translates it to llama-server / vllm / radiance argv at launch
  (`serve <model>`, `--max-model-len`, `--tensor-parallel-size`,
  `KV_CACHE_DTYPE`, `GPU_MEM_UTIL`, …; llama-only keys drop with a
  warning). Non-llama launches are GPU-only — an empty device is refused.
- The binaries registry carries a `type` (`llama` default, `vllm`,
  `radiance`); the preset editor switches its field set per type, and
  presets translate between backend types.
- `SERVER=` in a preset file pins the backend for file-mode presets;
  `start-model.sh` is now a backend dispatcher.
- RAM measurement and the swapper's fit logic are radiance/vllm-aware
  (process-tree Pss incl. vllm worker children; measurements stale on
  binary switch). Eviction rollback + swap-suite guard included.

## New build targets (`scripts/build_tools.sh`)

- **`radiance rocm`** — the radiance fork (C++/HIP RDNA4 server, `.rad`
  containers), built into the versioned bin tree.
- **`strata rocm`** (experimental) — HIP engine for Qwen3.8-Flash-Next
  (125B MoE, hot experts on GPU). Build convenience only; not
  launchable/adoptable by JayNet yet.
- **vllm preflight** — hard-fails early when the torch wheel's cmake link
  interface references hipsparselt but its cmake config is missing.

## llama.cpp shutdown fixes, carried as script patches

Vanilla llama builds apply three uncommitted patches after every sync:

- the upstream second-interrupt `exit()` → `std::_Exit()` one-liner
  ([ggml-org/llama.cpp#29581](https://github.com/ggml-org/llama.cpp/issues/29581))
  — model-swap service stops exit cleanly instead of coredumping in
  `~stream_session_manager()`,
- a nothrow `stop_gc()` guard,
- the stream-session cap (PR #30625).

Sync reverts `tools/server/` before ff-only pulls and refuses to pull over
local commits. Verified on b11795: mid-teardown double-SIGTERM exits
cleanly 3/3, single-SIGTERM loop 30/30.

## Upgrading

Pull, restart. No migrations. To use the new backends, register the binary
with its `type` in Admin → Models → Servers → Server binaries, then pick
that binary in a preset — the editor shows the matching fields.
