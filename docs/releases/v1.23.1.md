# v1.23.1 — typed config, batch C

Patch on 1.23.0. No behavior change on valid configs; the win is that
typos in the rail sections now warn instead of silently disabling a
safety rail. 2,334 tests green; live config validates with zero warnings.

## What changed

`runtime/config_schema.py` now models eleven sections: the original four
(`agent`, `budgets`, `tool_selection`, `eval`) plus the rail sections
`security`, `loop_guard`, `privacy`, `confirmation` and the ops sections
`web`, `models`, `processes`. Same soft-failure contract as before:
values coerce in place, unknown keys warn with a did-you-mean hint,
uncoercible values pass through with a warning — nothing is rejected.

Free-form maps whose keys are user data (`models.presets`, per-slot
process dicts, the `tools.*` namespaces) are deliberately dict-typed, not
closed models. The runtime-injected keys (`models.slots`, `gpu_info`,
`cloud` — layered in from the preset DB at boot) are schema-known now, so
admin config saves no longer warn on them.

The hand-written `except (TypeError, ValueError)` coercions downstream
stay on purpose: they are the backstop for the schema's soft-failure path
(uncoercible value → warn + keep raw). Removing them would turn a soft
warning into a hard type error inside a consumer.

Restart after pulling — the schema is on the boot path.
