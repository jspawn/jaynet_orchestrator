# JayNet v1.32.3 — guards_off in the benchmark UI + Strengths fix

Small patch: one feature completed, one regression fixed.

## Benchmark UI: rail ablation from the form

The benchmark variant row gains a **Without guards** column: comma-separated
guard names (`just_reply`, `verify_delegate`, `stall_check`, …) with name
completion from the new `GET /api/admin/evals/guards` endpoint (the three
guard registries plus the named dispatch gates). The backend accepted and
validated `guards_off` since the guard-ablation work — an unknown name fails
the variant with a 400, never silently runs with all rails on — but the form
had no way to send it. The monthly "does this rail still pay?" ablation is
now a form fill instead of an API call. One implementation note: the endpoint
registers before `/api/admin/evals/{case_id}`, because FastAPI matches routes
in registration order.

## Fix: Strengths pane lost its descriptions

v1.30.0 hid `models.strengths` from `GET /api/admin/config` (its home is
Admin → Models → Strengths, not the Runtime editor) — but the pane read its
descriptions from exactly that flat map, so every tag rendered empty. The
pane now reads `strengths_registry` from the presets payload (the live merged
config, overrides applied); role-temperature editing is unchanged.

## Upgrade

No config changes. Hard-refresh the admin console once (admin.js cache
buster v4) if the Strengths pane or the new column look stale.
