# v1.20.6 — Security hardening (still-open audit) + bounce-cap fallback

Patch release on 1.20.5. The claude "still open" re-audit
(`/srv/orch-dev-audits/claude_audit_still_open_06102026.md`) found one
real privacy hole and a cluster of fail-open role-policy defaults;
every claim was verified against the code first, then fixed with
regression tests. 2,275 tests green; ruff, mypy (193 baseline),
complexity (19 baselined), catalog, rails and doc-tools gates all
clean. No breaking changes; no config migration needed.

## The privacy hole: `all_owners` was confirmation-gated only

`runtime/owner_scope.py:owner_clause` and `tools/trace/owner.py:runs_clause`
lifted the per-owner filter for **anyone** passing `all_owners=true` —
and in a web chat the person approving the confirmation is the person
asking, so the gate was theater. The audit verified a non-admin context
could read another account's notes.

Now: a non-admin ctx passing `all_owners` is refused with
`PermissionError` (the loop and slash paths turn it into a normal tool
error), covering `memory.search/list`, `kg.*`, `rag.search/collections`,
`trace.query` and `trace.mine` at once, with a refusal test per store.
Admins keep the escape hatch (plus the confirmation), the ownerless
CLI/token path stays unfiltered.

## Role policy: fail closed, and it can't silently vanish

- **`/imp <local preset>` refuses non-admins.** The slash path built a
  `ToolContext` without a role — which defaulted to admin — and called
  `ModelUse().execute()` directly, bypassing the loop's admin-only
  dispatch. Any user could hibernate/swap the loaded models box-wide.
  The local `set` branch now checks the account's real role first.
- **`is_admin` defaults to `False`** in both `ToolContext` and
  `AgentRuntime.run` (was `True` — any forgotten flag was silently
  admin). The trusted operator paths (CLI, eval runner, boot posture,
  reflect, studio/eval drafts) pass `True` explicitly.
- **`model.measure` joined `security.admin_only_tools`** — it
  hibernates every model on the box for up to 30 minutes.
- **Code-side floor:** `admin_only_tools` now extends
  `runtime/loop.py DEFAULT_ADMIN_ONLY_TOOLS`. A missing or misspelled
  `security` key previously disabled the whole policy
  (`.get(...) or []`); the floor can't be removed by config, only
  extended.

## Privacy taint: `doc.pages` / `doc.tree`

Both pageindex tools returned document-derived content without
`private = True`, so the conversation was never tainted and the cloud
privacy gate never saw it. Fixed; the tool catalog shows the flags.

## Answer quality: bounce-cap fallback

When `agent.max_bounces_per_answer` suppressed an answer-**shape** guard
(`cap`/`trunc`/`empty`/`markup`), the loop accepted the broken
candidate as the final answer — the pinned test literally expected
`</ifm|tool_call>` to replace the real answer "12000".

The loop now tracks the last candidate that passed every shape guard
(they sit first in the registry, so a candidate whose first hit is a
content guard qualified) and falls back to it. A capped **content**
guard still accepts the current candidate — it is well-formed, only
its content is disputed. The `bounce_cap` event gains
`fallback: true|false`; the fallback resets with each new answer
sequence (tool work in between).
