# v1.5.0 — eval-harness hardening round

2026-08-28 · Fix + feature release. A cycle driven by measurement: a
124-case Terminal-Bench full-mode post-mortem and a full-suite proposal
triage found the bugs; this release fixes them and teaches the loop what
was learned. No breaking changes.

## Highlights

- **Terminal-Bench full mode grades what upstream grades.** Task images
  split into base + a thin test layer (`…-t<hash>`): pytest AND the tests'
  own pip deps (scanned from test imports) install at import time —
  16 tasks whose checks import cv2/pandas/psutil were unpassable before.
  Staged tests land at `/tests` (the upstream convention), containers can
  opt into network per case, and per-case `budget.turn_wall_clock_s` keeps
  one marathon task from eating a suite's evening.
- **The eval run-killers are dead.** The rendered LiteLLM config no longer
  shortens the seed timeouts (every local thinking turn >120 s died with a
  408 — ~25 % of one suite's failures); llama.cpp's malformed-tool-call-JSON
  500s now get one nudged retry instead of killing the run; benchlab test
  layers survive one unresolvable dep (v3).
- **Reflect: the harness learns from in-chat corrections.** Explicit
  corrections in *successful* sessions ("no, use uv instead of pip") are
  captured post-run, judged by the LOCAL brain (chat content never leaves
  the box), and filed as dedup'd, supervised proposals. Nothing
  auto-applies — same bar as eval proposals.
- **Judge overhaul.** The judge sees the case's own budget and is forbidden
  from proposing operator settings (global budgets, timeouts, proxy,
  network) — a live suite had produced dozens of unactionable, and
  dangerous-to-accept, config proposals. Config targets are whitelisted;
  the proposal inbox keeps one open item per (case, classification).
- **GAIA joins the benchmark roster** (gated HF dataset, level-1
  validation, attachments) — including the fix for HF's `"Final answer"`
  field spelling that skipped every row.
- **Eval tab ergonomics.** Results sub-tab, per-case deactivation (state in
  eval.db — survives re-imports), multi-select runs, row-level delete for
  custom cases.
- **Gate prompt: execution-discipline directives**, consolidated from a
  full suite's worth of accepted proposals: deliver-the-file (create +
  verify; chat is not a deliverable), sharper delegation, batched shell
  work, cross-checked counts, state the year, explicit memory recall,
  `council.vote` for high-stakes single answers, no permission-asking when
  the deliverable is clear.

## Upgrade notes
