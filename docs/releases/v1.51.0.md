# JayNet v1.51.0 — unified Saber families and evidence-guided experiments

This release expands the native Saber integration, makes long-running chats
survive transient browser disconnects, and turns harness lessons into bounded,
evidence-guided improvement cycles.

## Unified Saber model integration

- `scripts/saber-serve.sh` dispatches each `SABER_MODEL` to its native
  foreground launcher in the configured unified Saber checkout. The existing
  per-family scripts remain compatibility wrappers rather than separate copies
  of launch arguments.
- Reference presets cover Qwen3.8 27B TP1/TP2, Flash-Next, Ripple-65B,
  Kolibri-1, DaisyRose and Inkling 2 Mini. Occamy FP8 remains experimental.
- Model assets stay operator-managed at their configured paths. Servers bind to
  loopback and use the existing preset lifecycle, process-group shutdown and
  admin telemetry.
- Kolibri uses optimized prefill defaults, automatic tool selection bounds
  Saber cold prefill, and Inkling vision launches account for projector memory.
  Occamy's slower Saber MTP path is disabled.

## Stable prompts and prefix-cache reuse

- Ripple presets keep changing datetime, guard and todo notes out of the initial
  system prompt, avoiding needless prefix invalidation.
- Per-preset `profile.tool_selection` can keep the advertised tool schema set
  stable (`"all"`). Explicit tool allowlists and disabled-tool restrictions
  still take precedence.
- These changes address prompt-prefix changes that prevented cached follow-ups;
  model swaps and server restarts still invalidate Saber's in-memory cache.

## Evidence-guided harness experiments

- Lesson retrieval ranks completed experiments by matching case, shared tags
  and brain. Proposers see supported, no-effect and regression outcomes, including
  warnings not to repeat failed edits without new evidence.
- Experiments can run one or two sequential Propose–Probe–Compose cycles. The
  second cycle carries the first composed overlay forward, and every cycle stays
  visible in history with an overall initial-baseline comparison.
- Only measured overall improvements can create acceptance proposals. Regression
  and no-effect outcomes remain inspectable without offering a misleading fix.
- Multi-edit proposals use canonical overlay schema 2. Run-precedence stacking,
  eval delivery and judge-state resolution preserve the exact overlay tested.

## Chat stream reliability

- Transient SSE disconnects now retain the native EventSource reconnect instead
  of closing the stream and abandoning the browser-side turn.
- Replays resume through `Last-Event-ID`; terminal HTTP failures still close the
  stream. A model run can therefore finish and render normally after a short
  network interruption.

## Dependency update

LiteLLM is pinned to **1.110.2**. Sync the main, tools and LiteLLM lockfiles
before restarting the services.

## Verification

The release gates cover the full Python test suite, Ruff, mypy, complexity,
prompt budgets, generated docs/rails, dependency audits, ShellCheck, JavaScript
syntax and diff hygiene. Native Saber acceptance was exercised separately per
available model family; models without required local assets are not claimed as
GPU-validated.

## Upgrading from v1.50.0

SQLite migrations are additive and automatic. Existing slots, priorities,
presets and overlay histories are preserved:

```bash
git fetch --tags
git checkout v1.51.0
uv pip install --python .venv/bin/python -r requirements.lock
uv pip install --python .venv/bin/python -r requirements-tools.lock
uv pip install --python litellmenv/bin/python -r requirements-litellm.lock
systemctl --user restart jaynet-web litellm-proxy
scripts/orch --doctor
```

Saber remains opt-in. Set `SABER_REPO` to the unified checkout and verify each
preset's model assets before assigning a live slot. No model downloads, checkout
changes or slot reassignments happen automatically.
