Adopted endpoints with API keys, CI with a ruff baseline, scheduled eval runs, a near-duplicate loop guard, and one-click benchmark-to-slot routing.

- **API keys for adopted endpoints** — a remote preset gains an *api key env* field (admin → Presets): the NAME of an env var in `~/.config/jaynet.env`. The key never touches the preset DB or litellm.yaml; probes send it as a Bearer header and distinguish "no key configured" from "key rejected".
- **CI + ruff baseline** — every push/PR runs ruff and the full pytest suite on Python 3.11 + 3.12 (3.11 is now the declared minimum).
- **Scheduled, version-tagged eval runs** — Admin → Eval → Scheduled runs fires a suite unattended on an interval (`case:<id>` or `tag:<tag>`, 1–720 h); skipped while any suite runs, auto-disabled when its selector goes stale. Every result now records the JayNet version, so eval.db is a quality ledger across releases and brain swaps.
- **Near-duplicate loop guard** — the loop guard now catches the same search reworded ("price 2026 CHF" → "24h price CHF 2026"): the third similar query-like call is blocked with a synthesize-now error. Genuinely different queries pass untouched.
- **Benchmark-informed routing** — the Benchmark compare view crowns the ★ winner and offers a one-click *route it*: assign the winning preset to a slot (human-gated, restart-to-apply).
- **Audit fixes** — keyed endpoints no longer probe as dead in `live_slot`/​/imp, schedule toggle validates its body, eval versions sort numerically.
