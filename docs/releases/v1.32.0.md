# JayNet v1.32.0 — schedules: cron, projects, flags, history

The prompt scheduler grows up. What existed (a JSON store, a 30-second
ticker, chat-only `schedule.*` tools for admins) now has the four things a
real automation feature needs: **proper timing, a place to put output, an
access dial, and a memory.**

## What's new

**Cron timing.** Next to one-shots (`+30m`, ISO-8601) and intervals
(`30m`/`2h`/`1d`/`1w`), a schedule can be a 5-field cron expression in
local time — `30 7 * * 1-5` fires at 07:30 on weekdays. Steps, lists and
ranges work; dom/dow follow classic cron OR-semantics. A malformed
expression disables the entry instead of stalling the scheduler.

**Project attachment.** A schedule can point at a project; the fired run's
workspace is that project's files dir, so "pull the fresh data via the ERP
connector, reshape it with the chain, write the report" lands its file
right where the rest of the project lives. Chains, connectors and tools all
work inside a scheduled run — the prompt is the payload.

**Per-user access flag.** Scheduling is no longer admin-only. Admin → Users
gains a Schedules toggle; allowed users create and manage their own
schedules from chat (`schedule.add`/`schedule.remove`), gated per run at
the web layer. Revoking the flag auto-disables the user's entries at the
next tick. The trust model didn't move: only an admin-owned schedule may
auto-confirm gated tools — a non-admin's scheduled run always asks.

**Status and history.** The new top-level **Schedules** tab shows every
entry from every user: enabled toggle, next fire, last-run status pill,
fire count, delete. Each row expands into its run history — the last 50
firings with status, duration, excerpt and tokens. History lives in a new
`schedule_runs` table and is wiped when an account is deleted.

## Upgrade notes

- No config changes required; `tools.schedule` keeps working as-is.
- `schedule.add`/`schedule.remove` left `security.admin_only_tools` —
  non-admin accounts see the tools only when an admin grants the flag.
- After updating, hard-refresh the admin console once (new admin.js/css).

All gates green: full pytest suite, ruff, mypy baseline, complexity,
prompt-budget, rails and catalog checks.
