# JayNet v1.32.2

Six tags since v1.28.0 (v1.29.0 → v1.32.2). The headline: **schedules are
a first-class, manageable feature**, the **admin console was reorganized
around build / operate / measure**, the core toolset got **30% leaner on
every turn** (measured, no regression), and **BFCL v4** joined the eval
bench. Plus an audit pass with real fixes.

## Schedules (v1.32.0–1.32.2)

- New top-level **Schedules** admin tab: create form (owner, prompt,
  timing, project, enabled), table with enable/delete + last-run status,
  expandable history (last 50 firings: status, duration, excerpt, tokens).
- **Cron schedules** — `once` (`+30m` / ISO-8601), `every` (`2h`, `1d`…),
  or 5-field cron in local time with classic dom/dow OR-semantics.
  Impossible dates ("Feb 30") reject in milliseconds (the scanner is
  day-based now; the minute scan could stall the web server under the
  store lock).
- **Schedules attach to projects** — the fired run's workspace is the
  project's files dir, so output lands with the project.
- **Per-user schedules flag** — `schedule.add`/`remove` are no longer
  admin-only: Admin → Users grants `schedules_allowed` per account.
  Revoking auto-disables self-created entries; admin-planted entries
  (`created_by: admin`) keep firing and are managed from the admin table.
- Scheduled runs never hit a TTY confirmation prompt (refuse-everything
  provider), and slash-typed `/schedule.add` respects the same gate.

## Admin console: build / operate / measure (v1.31.0)

- **Studio** (things you build) and **Eval** (measurement) are separate
  top-level tabs; Connectors and Plugins moved to Studio, MCP stays in
  Harness. Legacy URL hashes redirect.
- Connector management actually works from the UI: the ro/rw dropdown and
  enabled toggle no longer 422 silently, `.jayconn` import fixed, and the
  dropdown explains itself ("read-only · write tools off" / "read-write ·
  writes ask in chat").
- admin.html extracted into admin.css/admin.js (4,799 → 1,067 lines of
  markup) — browser-cachable, covered by the static-JS guards.
- Themed checkboxes everywhere (v1.29.0), completing the
  one-control-language work.

## A leaner, measured brain (v1.30.0)

- **Core toolset trim: 18 → 13 always-on tools (−30% schema tokens per
  turn)**, evicted by tool-value data over 3.9k traced runs. All five
  evicted tools stay reachable via keywords or `tools.load`.
- **BFCL v4 in benchlab** (~120 cases, tag `bfcl`) plus stub-tool eval
  cases: case-declared function schemas, the run restricted to them, and
  argument-level grading against the trace (BFCL AST rules). First live
  numbers: ~77% overall; the failures have cleanly measured causes.
- **Office files out of the box again** — the devbox image ships
  python3-docx/openpyxl/pptx; the docx/xlsx/pptx skills lead with the
  devbox path and "never write your own converter".
- Runtime config editor hides dead-end keys (DB-seeded and boot-only
  settings no longer pretend to be live-editable).

## Fixes worth knowing (v1.31.0–1.32.2)

- **Config-reset tombstone:** resetting a YAML-absent override wrote a
  `None` into the live config and crashed auto-mode tool selection —
  resets now delete the key.
- **Follow-up context no longer strands connector namespaces** (v1.32.1):
  keyword tool selection scans the last few chat turns
  (`tool_selection.history_turns`, default 3), and a new `phantom_tool`
  dispatch gate refuses call-shaped references to known-but-unloaded tools
  with the real recovery path (`tools.load`).
- **Audit pass (v1.32.2):** slash commands enforce the full tool policy
  (global disable list + schedule gate — they bypassed both); eval stub
  tools can't leak into the live registry when a case skips; `code.patch`
  uses the safe git flags; schedule docs match actual behavior.
- **build_tools.sh moved into the repo** (v1.32.1): the GPU build helper
  ships at `scripts/build_tools.sh` with pinned forks and sha256-checked
  patches; builds live in `~/jaynet-build`, outside the checkout.

## Upgrade notes

- No config changes required. Existing schedule entries are treated as
  self-created (unchanged revocation behavior).
- The devbox image gained the Office libraries — rebuild with
  `scripts/devbox-build.sh` if you use the docx/xlsx/pptx skills.
- If you built models with the standalone helper_scripts clone: it's
  archived; use the in-repo `scripts/build_tools.sh` (run once with
  `BUILD_HOME=<old checkout>` or move the trees into `~/jaynet-build`).
