# v1.25.1 — strengths admin UI, measured VRAM everywhere

Models tab ergonomics: the strength-tag registry no longer needs a YAML
edit, the presets table shows real measured footprints, and measuring is
a button. 2,358 tests green; all gates clean.

## Admin → Models → Strengths card

The tag registry (`models.strengths` name→meaning + `agent.role_temperature`)
was code/config-only — adding a tag meant editing `runtime.yaml` plus the
typed schema. The new card lists every tag (description, child temperature,
carrier presets), adds new ones, edits inline, and resets to shipped
defaults. Entries persist as admin config overrides via the existing
`PUT /api/admin/config` dotpath machinery and apply on the next run — no
restart. Edge fixed along the way: the config editor's reset writes a
cleared dotpath back as None, which `strength_registry` rendered literally
— falsy descriptions are filtered now.

## Presets table: measured VRAM, strengths multiselect, measure button

- The VRAM column rendered only the `vram_gib` hand estimate — measured
  presets showed blank. Now: `30.5 ✓` measured (tooltip: date, per-GPU
  split, RAM), `30.5 ~` stale per the planner's own `_measured_current`
  rule (exposed as `measured_stale` in the payload), `12?` estimate,
  `—` unknown.
- The editor's free-text strengths field is a checkbox group fed by the
  registry (allround + registered tags; unregistered tags a preset
  already carries stay checked, marked `unregistered`).
- Local rows get a **measure** button: `model.measure` as a background
  job (`POST /api/admin/presets/{name}/measure` + status poll, one at a
  time), the click standing in for the tool's confirmation.
