# v1.9.1 — audit #17 fixes

2026-09-10 · Fix release on top of v1.9.0's swap planner.

## B1 — brain eviction is internal-only (security)

v1.9.0 exposed `include_brain` as a model-facing `model.use` argument while
the docs promised direct swaps can never evict the brain. A direct or
prompt-injected `model.use(preset, swap: true, include_brain: true)` could
have stopped the current run's own model mid-turn — with no swap-back on
the direct path, the box stays brainless until a human restarts it.

Now: the flag is gone from the tool schema, and `execute` only honors
brain eviction when the caller raised the internal
`ctx._allow_brain_evict` — which `code.delegate` does around its
ModelUse call (and always re-lowers), because delegate's swap-back
restores the brain before the parent's next turn. Pinned by
`test_include_brain_arg_is_inert_for_model_calls` /
`test_include_brain_honored_with_internal_ctx_flag`.

## C1 — smi probe off the event loop (perf)

`GET /api/admin/presets` (and the preset/GPU/binary save routes) return
`_presets_payload()`, which probes live VRAM via a synchronous
rocm-smi/nvidia-smi subprocess (timeout 20 s). The routes now build the
payload via `asyncio.to_thread`, so a slow or hung smi can't stall the
whole web console — the same loop-blocking class the swap planner's
probes already avoid.

## D2 — playbook counts (docs)

`docs/playbook.md` said 117 tools / 38 namespaces; the generated
`docs/catalog.md` holds 118 tools / 40 namespaces (plus 10 plugin tools in
3 plugin namespaces, counted separately). Fixed to the generated numbers.
