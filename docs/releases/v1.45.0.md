# JayNet v1.45.0 — managed Saber Flash-Next

This feature release adds native Qwen3.8 Flash-Next TP2 support to JayNet's
Saber preset and lifecycle management. Existing 27B presets are unchanged.

## Flash-Next presets

Use `presets/specialist-qwen3.8-flashnext-saber-tp2.conf` with the existing
`saber`-typed binary. `SABER_MODEL=flashnext` selects the new native launcher,
which provides:

- two-GPU TP2 and trunk8 pack validation;
- FP8 KV and 262,144-token context defaults;
- agent-load tuning and lazy vision;
- the catalog's served model ID;
- graceful SIGINT process-group shutdown when JayNet stops the slot.

Flash-Next does not need the 27B's separate DFlash2 pack. Fetch its pack and
referenced checkpoint with:

```bash
SABER_PACKS=$ORCH_MODELS/saber-models/saber-packs \
  ~/jaynet-build/saber-rocm/tools/fetch_packs.sh flashnext
```

Keep the original checkpoint at the absolute path recorded in the pack manifest
and PLE index. The managed Flash-Next path is native-only; the 27B container
fallback remains available only for 27B.

## Upgrading

Pull and restart both services so the launcher and generated proxy configuration
are current:

```bash
systemctl --user restart jaynet-web litellm-proxy
```

Create or import the Flash-Next preset if it is not already in your catalog,
then place it at the desired priority. Boot model slots require no changes.
