# JayNet v1.38.0 — scoped selftest, bash-only control, cache telemetry

## Scoped `/selftest`

- Bare `/selftest` shows help (no more accidental full runs); `all`, `tools`,
  `skills` or explicit tool/skill names run a bounded self-test.
- New private `trace.coverage` tool: compares a run's advertised tools with
  its actual `tool_result` events — ok / ok-after-retry / failed / not-run —
  plus skill discovery, so the report comes from the trace, not the model's
  memory.
- `/api/tools` returns skill names too (composer completion).

## Service error reporting fixes

- `ops.status` pings LiteLLM with the master key when set — keyed installs no
  longer show HTTP 500 as "down".
- `audio.transcribe` distinguishes unreachable / rejected-request /
  server-error instead of always saying "assign a preset".

## Bash-only eval control (harness lessons #1)

- Benchmark variants gain `tools_only` (exact tool restriction, intersected
  with the unattended-safe set) and `base_system` (whole-prompt swap from
  `prompts/<name>.md`); ships `prompts/eval-bash-agent.md`.
- A variant with `code.run` + `eval-bash-agent` is the mini-SWE-agent-style
  control: same cases, same judge, bare bash agent — the delta against `full`
  is what the JayNet toolset, skills and routing add.
- Unknown tool/prompt names fail loudly at case load; *Tools only* and
  *Base prompt* columns in the benchmark UI (plus the missing *Without
  guards* header).

## Cache telemetry (harness lessons #4a)

- Model turns record `turn_s` (whole exchange) and `ttft_s` (streaming
  path); the `model_turn` trace event carries `cache_hit_ratio`.
- Eval results store a tokens-weighted `cache_hit_ratio` column (migration;
  legacy rows stay blank); the benchmark Compare view shows `% cache` per
  variant cell and overall row.
