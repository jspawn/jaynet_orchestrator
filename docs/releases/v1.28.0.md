# JayNet v1.28.0 — strengths, telemetry and one control language

Rollup of v1.25.0–v1.28.0 (the individual releases were folded into
this one). Since v1.24.1: model strengths are admin-managed, tools and
strengths are measurable from the live trace DB, presets show real
measured VRAM, the admin console speaks one control language — plus a
full documentation and screenshot refresh. 2,365 tests green; all CI
gates clean.

## Admin → Models → Strengths card

Manage the tag registry (`models.strengths` name→meaning +
`agent.role_temperature` child temperature) without touching YAML: list
(with carrier presets), add, inline edit, reset-to-shipped. Entries
persist as admin config overrides and apply on the next run — the
brain's strength directory renders per run, so a new tag is routable
immediately (`specialist.delegate strength="…"`). Shipped defaults can
be edited and reverted; custom tags disappear on reset.

## Presets table: measured VRAM + measure button

- **VRAM shows the measured footprint** (`model.measure`) instead of
  only the hand estimate: `✓` current measurement (tooltip: date,
  per-GPU split, RAM), `~` stale (ctx/GPU edited since — re-measure),
  `?` estimate, `—` unknown.
- **Measure button per row** (local, aliased, non-archived presets):
  runs `model.measure` as a background job — one at a time. The VRAM
  cell refreshes on done.
- Device and strengths are themed multiselect dropdowns (button +
  checkbox popover) instead of inline checkbox rows; CPU stays
  exclusive with GPU picks, tag meanings ride the option tooltips.

## Tool telemetry, standing

`scripts/tool_value.py` reads the live trace DB (read-only) and prints
per-tool calls, error rates, run share and ok-rate contrast — also as
the **Tool telemetry** card in Studio & Eval → Eval. This turns "which
tools earn their keep / what do we trim or develop" from a prose debate
into a query. First readings: `architect` called once in 3.9k runs, the
`research.*` state spine nearly untouched, `note.set` 26×
`memory.append`, `web.fetch`'s 33% error rate is the escalation ladder
working as designed.

## Strength matrix: transposed, shaded, registry-driven, archived-filtered

Brains run downwards, strengths across; the top-3 cells per strength
get decreasing green shades. Case→strength mapping matches case tags
against the registry directly: tag a case `bugtrace` and it measures
under `bugtrace` with no code change. The Compare picker and matrix now
default to labels mapping to a current catalog preset — retired brains
and harness variants sit behind a synced **show archived** toggle.

## One control language

`select` and `button` share the input styling — same font, size, panel
background and border — so boot model slots, benchmark dropdowns and
every native select stop rendering in the OS-native look.

## Upgrade notes

Pull, restart, done — no config or dependency changes. To fill in VRAM
numbers for your own presets, click **measure** per row (Admin → Models
→ Presets) — one at a time, the box blinks while it runs. New strength
tag → new measurement: add a case tagged with your custom strength and
watch the matrix fill in.

Note: the ORCH_* env fallback stays until the first release on/after
2026-12-01, per the documented drop date in docs/upgrading.md.
