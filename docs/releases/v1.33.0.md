# JayNet v1.33.0 — the routing scorecard

Minor release answering one question with numbers: **does the
brain + specialist split actually pay?**

## Benchmark compare: tokens + delegation rate

Every compare cell now carries, next to pass rate / score / cost / elapsed:

- **avg tokens** — what the run cost in context, not just dollars
- **delegation rate** — the fraction of the variant's runs whose trace shows
  `specialist.delegate`/`code.delegate` (how willingly the brain hands work
  off; `agent.spawn`/`architect` are same-brain/planning verbs and don't
  count). Trace-derived — no manual classification, nothing to maintain.
  The trace db is retention-pruned, so old results degrade to a 0 rate
  instead of failing the compare.

The overall row averages both per label.

## The predefined set: tag `routing`

Twelve delegate-worthy cases carry the new `routing` tag (the five code-*,
both rlm-*, eureka scaling-law + extrapolation, delegate-coding,
delegate-strength-routing, j-space-loop), so the monthly "does routing
pay?" run is comparable over time:

- tag `routing`, variants `brain-only` (harness `brain`) and `full`
  (harness `full`), same brain alias and sampling on both — the column
  delta is the harness, not the model; the deleg% column shows whether the
  brain used the specialists it had.

## Strength matrix: all defined strengths render

Columns were built only from measured results, so unmeasured strengths
(`multi-step`, `creative`, `osint`, …) were invisible. The endpoint now
returns the registry with the cells, and every defined strength gets a
column — empty ones are the coverage map. To fill them: tag cases with the
strength name (or `strength:<tag>`) and run a variant over them.

## Upgrade

No config changes. Hard-refresh the admin console once (admin.js cache
buster v6).
