# JayNet v1.32.1 — follow-up context fix (selector stickiness + phantom gate)

Patch release fixing a live failure: "count the people in the erp demo"
worked; the follow-up "lookup all users named Christian Fischer and give me
their email" re-selected tools from the new message only, dropped the
`erp_demo` namespace, and the brain — remembering `erp_demo.search` from the
transcript — hallucinated it as a shell/python call and spent 24 turns
searching the filesystem for an "erp_demo" package before the run was
cancelled by hand.

Two fixes:

- **Sticky namespaces.** Keyword-based tool selection now also scans the
  last few chat turns (`tool_selection.history_turns`, default 3, bounded
  to ~2000 chars, 0 disables). A namespace loaded earlier in the
  conversation stays loaded for keyword-free follow-ups.
- **Phantom-tool gate.** A call-shaped reference to a *known* JayNet tool
  that isn't in the run's toolset — `erp_demo.search(...)` written into a
  `code.check`/`code.run`/`code.execute` command — is refused before
  execution with the actual recovery path: "call `tools.load` with the
  namespace, then invoke it as a tool." It never blocks legitimate code:
  the referenced tool being allowed (or unknown) passes straight through.

Diagnostics mark history-triggered namespaces as `"keyword (history)"` in
the tool_selection event, so a trace shows why a namespace was loaded.

No config changes required on upgrade. All gates green (full pytest suite,
ruff, mypy, complexity, rails, prompt budget, catalog).
