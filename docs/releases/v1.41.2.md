# JayNet v1.41.2 — versioned per-brain overlays

This release turns accepted eval lessons into reversible, per-preset harness
adapters and includes another reliability pass over the behavioral eval runner.

## Versioned brain overlays

- New prompt, skill, tool-description and config proposals retain the brain
  preset and overlay base version that produced their evidence.
- Accepting a proposal appends a complete snapshot to `preset_overlay_versions`
  in `presets.db`; other brain presets and global custom artifacts stay intact.
- Overlays hot-apply with explicit run/experiment overrides taking precedence.
- Accept is idempotent, stale-base proposals are refused, and rollback appends
  a copy of any older snapshot, including the empty version-0 baseline.
- Harness experiments create one atomic brain-overlay proposal for the composed
  edit. Eval results record overlay version and content hash.
- Admin → Eval → Proposals provides target-brain details, snapshot inspection,
  version history and restore controls. Nothing applies automatically.

Legacy proposals without a brain identity keep the previous global behavior.
Review old pending suggestions before accepting them; do not treat stale
infrastructure reports or benchmark-specific advice as general overlay lessons.

## Eval reliability

- GAIA final-answer extraction accepts the marker line when trailing prose is
  present.
- Specialist verification supports `expected_exit`, including expected-red TDD
  phases.
- Council evaluation requires `council.vote` before any additional recomputation.
- BFCL stub guards clean up correctly and report attempted, executed and blocked
  calls more clearly.

## Documentation

Admin screenshots are refreshed, including the new Proposals and Brain overlays
view. README, playbook, architecture, testing and learning documentation cover
the new storage and review workflow.

## Verification

**2,695 tests pass**, along with Ruff, complexity, mypy, prompt/documentation
checks, dependency audits, shellcheck and frontend syntax checks.

## Upgrading

Pull and restart JayNet. Database migrations run automatically; no config change
is required. To align installed dependencies with the tested lockfiles:

```bash
uv pip install --python litellmenv/bin/python -r requirements-litellm.lock
uv pip install --python .venv/bin/python -r requirements-tools.lock
```

The separate LiteLLM environment moves to `litellm==1.102.2`; the tools set
includes `mcp==2.2.0` and `aiohttp==3.14.4`.
