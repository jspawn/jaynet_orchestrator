# JayNet v1.43.2 — native Saber and SQLite race fix

This patch release switches Saber's default build/runtime to the verified
host-native path and fixes a concurrent overlay-store initialization failure.
No dependency, database or configuration migration is required.

## Native Saber

- `scripts/build_tools.sh saber rocm` now builds the pinned Saber release
  directly with cargo instead of requiring Podman or Docker.
- The new native launcher uses upstream's shipped gfx1201 kernels, validates
  TP-specific packs and binds to loopback by default.
- The lifecycle wrapper runs the engine in a separate process group and
  translates JayNet's SIGTERM into Saber's graceful SIGINT, including TP ranks.
- Existing `$BIN_DIR/saber.rocm/bin/saber` registrations and TP1/TP2 presets
  keep their paths and need no catalog changes.
- The previous container build/runtime remains a deliberate fallback:

  ```bash
  SABER_BUILD=container scripts/build_tools.sh saber rocm
  ```

## Overlay-store reliability

Concurrent first-time overlay accepts could fail with `sqlite3.OperationalError:
database is locked` while enabling WAL. The store now sets `busy_timeout`
before the WAL PRAGMA and retries transient WAL/schema lock errors for up to
10 seconds. A locked-writer regression covers the wait path; the original
concurrent-accept regression passed 50 consecutive repetitions.

## Verification

- **2,815 tests passed**.
- Ruff, complexity, mypy, generated docs, prompt budgets, Shellcheck and all
  dependency audits pass.
- No full native rebuild or GPU server was started during this release pass.

## Upgrading

Pull and restart the web service for the SQLite fix:

```bash
systemctl --user restart jaynet-web
```

Saber users can opt into the native binary after pulling:

```bash
BIN_DIR=/srv/jaynet-bin AMDGPU_TARGETS=gfx1201 \
  scripts/build_tools.sh saber rocm
```

Restart the affected model slot after the build switches the stable symlink.
