**Self-documenting admin + selftest fix round.** v1.0.2 is what a live selftest (kimi-k3 driving the shipped selftest skill against the whole toolset) plus a documentation pass over the admin tabs turned up: two cloud-catalog footguns, a missing browser-setup path on fresh installs, and an admin console that now explains itself. Suite: 1176 tests, ruff clean.

The short version for upgraders: pull, restart, done — no config or data migration needed.

Highlights:

- **Admin → Config explains itself** — every one of the ~300 settings shows a one-line explanation under its label, served from the shipped `config/config-help.yaml`. A coverage test fails the suite if a key ever ships without help, so the on-screen docs can't rot. New [docs/configuration.md](../configuration.md) maps the config layers and sections.
- **Admin → Tools shows real descriptions** — the per-tool tooltip was always empty (the API never sent descriptions); all 113 tools now carry their one-liner inline, filter included.
- **Headless-browser setup is distro-aware** — `browser.*`/`web.render`/`pdf.create` died on fresh installs; `setup.sh --with-tools` now resolves the platform (system chromium / pacman / apt / `playwright install`) and `orch --doctor` tells you which path wins.
- **Cloud catalog fixes** — the `gemini-pro` seed pointed at a model id that doesn't exist, and the cloud store now rejects the OpenRouter `api_base` + missing `openrouter/` prefix combination that made LiteLLM silently drop a deployment (the alias vanished from `/imp`).
- **Eval proposals land cleaner** — judge meta-phrasing ("Add a directive: …") is stripped on accept, so accepted prompt tweaks read as directives to the model instead of notes to a human.
- **`code.patch` lenient retry** now passes `--recount`.
