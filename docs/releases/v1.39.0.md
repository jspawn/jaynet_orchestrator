# JayNet v1.39.0 — harness lessons: ledger, model profiles, protocol v1

Completes the harness-comparison program (`docs/harness-lessons.md`): all
four lessons are now shipped (bash-only eval control and cache telemetry
landed in v1.38.0).

## Acceptance ledger + clean-state verification (lesson #3)

- Todo items and requirements can declare a machine check (`check` field or
  `| check: <cmd>` suffix). Marking one done runs the check through the
  verify sandbox (fail-closed, vacuity guard); `todos action=verify` re-runs
  on demand.
- `verified` is harness-set only: the requirements gate demands a checked
  `[must]` be VERIFIED, not just done — "done" is the model's say-so, the
  check is the proof.
- The plan writes through to `<workspace>/ledger.json` and rehydrates
  across /goal iterations (same criterion only — no stale-plan
  inheritance).
- Opt-in clean state (`agent.ledger_commits`): a checked item going working
  snapshots the pre-increment tree, its check must fail on that baseline
  (red→green), and each verified increment is offered as a
  confirmation-gated `ledger: <title>` commit.
- UI: check-state markers in the ToDos panel and a `ledger_check` chat-feed
  row. Kill switch: `agent.ledger_checks`.

## Per-model harness profiles (lesson #4b)

- A preset can carry a JSON `profile` with per-model overrides for behavior
  that was global config or hardcoded:
  - `think_strip`: qwen3 | gemma4 | both | none — think-strip/split
    (including the streaming splitter) is now family-aware.
  - `reasoning_budget_tokens` (explicit 0 disables), `compaction`,
    `anchor`, `sampling`, `role_temperature` (per-tag fallback for
    delegated children).
- Precedence everywhere: run overrides > preset profile > global config >
  built-in default — an unconfigured preset behaves exactly as before.
- Resolution rides the config layer, so admin edits hot-apply without a
  restart. The preset editor gained a harness-profile JSON textarea.

## Protocol v1 — typed events + versioned REST (lesson #2, stages 1–2)

- `runtime/protocol.py` declares all 44 SSE event types with their
  required/optional payload fields, plus the single `build_envelope` the
  loop's emit seam and every web fast-path now share — the wire shape can
  no longer drift between producers.
- Payloads validate at the seam: warn-once in production, strict in tests
  (a fake-model loop run under `STRICT=True` is the meta-guard against
  future unregistered emit sites).
- New `/api/v1/*` endpoints: `POST /api/v1/runs`, `GET /api/v1/runs/{id}`,
  `GET /api/v1/runs/{id}/events` (SSE; `Last-Event-ID` plus an additive
  `?after_seq=` resume parameter), `POST …/cancel|approve|answer` — thin
  wrappers over the same internals as the unversioned routes, which remain
  supported aliases.
- Wire bytes, field names and auth are unchanged; existing clients (web UI,
  Android) need no changes.
- Stage 3 (server-side threads) stays parked until the Android client grows
  cross-device resume.

## Upgrading

No migrations or config changes required. New optional knobs:
`agent.ledger_checks` / `agent.ledger_commits` (runtime.yaml), preset
`profile` JSON (admin preset editor). See `docs/upgrading.md` for the
standard pull-and-restart procedure.
