# JayNet v1.51.1 — chat recovery and patch robustness

This patch release fixes lost chat turns after browser stream interruptions and
a common unified-diff formatting failure seen during local-model selftests.

## Chat recovery across disconnects and reloads

- Closed SSE connections now query the authoritative `/api/v1/runs/<id>` status.
  Live runs reconnect; completed runs restore their final answer even after the
  two-minute in-memory event replay has expired.
- Transient `CONNECTING` errors continue to use the browser's native EventSource
  retry and `Last-Event-ID` replay.
- The in-flight prompt, attachments and turn metadata sync at run start rather
  than only at turn completion. Reloading or opening another device restores the
  original prompt and resumes the same run.
- Older snapshots can recover their prompt from replayed `run_start` data. The
  final-answer status fallback also handles runs whose replay is already gone.

The web client cache buster is now `app.js?v=56`; hard-refresh only if an older
client remains cached after upgrading.

## Unified-diff robustness

- `code.patch` repairs truly empty lines inside diff hunks into unified-diff
  blank context (one leading space). Added and removed blank lines still require
  their explicit `+` or `-` marker, and text outside hunks remains unchanged.
- The tool description and selftest playbook document blank context and the
  default `strip=1` behavior for `a/`/`b/` paths.
- Context matching and allowed-root checks remain enforced; this is not fuzzy
  patching and does not permit incorrect content or paths.

## Verification

The full Python test suite, Ruff, mypy, complexity, prompt budgets, generated
docs/rails, dependency audits, ShellCheck, JavaScript syntax and diff hygiene
all pass.

## Upgrading from v1.51.0

No dependency or database changes are required:

```bash
git fetch --tags
git checkout v1.51.1
systemctl --user restart jaynet-web
scripts/orch --doctor
```

Restarting LiteLLM is unnecessary for this patch unless it was not restarted
after the v1.51.0 dependency update.
