# JayNet v1.50.0 — model orchestration, durable work and trustworthy evals

This is the cumulative public release since **v1.40.1**. It rolls up v1.41.0
through v1.45.2, plus native Occamy FP8 Saber support and a refreshed llama.cpp
shutdown-patch rebase.

## Unified model routing and safer swaps

- Admin → Models → Presets is now one drag/drop priority list. Exact strength
  matches route in catalog order, followed by `allround`; the first eligible
  brain is the universal final local fallback.
- Failed model loads and generation probes restore evicted models before any
  fallback child runs. Successful specialist runs restore the brain before the
  parent continues, including two-GPU, one-GPU and conservative CPU-only plans.
- Request failover accepts only verified-live, allowlisted and
  payload-compatible presets. Shared public aliases retain exact-preset routing;
  the old static specialist-to-brain proxy fallback is removed.
- Benchmark variants can restrict all routing, swaps, spawned children and
  explicit LLM calls to named presets without changing the live catalog.

## More local engine choices

- Opt-in Saber ROCm builds support Qwen3.8-27B TP1/TP2 weight packs, native or
  container execution, graceful shutdown and admin resource reporting.
- Managed Flash-Next TP2 launches support strict templates, quantized checkpoint
  metadata, 262K context, lazy vision and process-group shutdown.
- An experimental Occamy FP8 Saber preset and native launcher are included for
  two-GPU setups. Model packs and compatible forks remain explicit operator
  choices; nothing downloads or converts them automatically.
- vLLM and radiance process cards report throughput, Hugging Face downloads
  recognize `.rad` containers and recipes, and update watchers appear only when
  the corresponding engine is installed or active.
- The llama.cpp safe-exit patch applies to current upstream again, retaining
  graceful model-service stops without stale local-patch conflicts.

## Better context with less noise

- Explicit memory questions can prefetch owner-scoped local memories. RAG recall
  requires a configured or explicitly named collection; automatic RAG stays off
  until `tool_selection.recall.collection` is set.
- KG aliases canonicalize alternate entity names, with confirmation-gated merges
  and weighted associations. RAG score filtering happens before reranking.
- Evidence-aware compaction collapses superseded file reads, preserves command,
  exit status, output head and error tail for old logs, keeps pinned/recent
  results verbatim and leaves full output recoverable through `trace.query`.

## Delegation and automatic workflow selection

- Ordinary specialist children share the parent's effective workspace, including
  scratch-only runs; explicit isolated worktrees remain separate.
- Children inherit eval store/container redirects and can use read-only memory,
  KG, Graphify and RAG retrieval narrowed by the parent's allowed tools.
- Vision is resolved per target preset rather than inherited from the brain.
  Strict specialist chat templates and null tool-turn content are normalized.
- Deterministic gates cover architect, codebase review, debugging, diff review,
  deep research and presentation workflows without requiring magic keywords.
  `visual-web` and `dom-analysis` strengths route browser/DOM work explicitly.
- Delegate activity names the selected model and whether routing was automatic,
  manual or strength-triggered.

## Durable schedules and quiet watches

- Each scheduled-prompt occurrence creates a durable work item with recorded
  execution attempts, atomic queued-attempt claims and startup reconciliation.
- Scheduled-result chat delivery uses a deduplicated outbox, reducing lost or
  duplicate completions around crashes. Recovery remains deliberately
  at-least-once; JayNet does not claim exactly-once agent execution.
- Observe-only arXiv watches record newly discovered papers for review without
  automatically launching agent work.

## Evals that measure the intended model

- Accepted lessons target versioned per-brain overlays rather than global prompt,
  skill or tool artifacts. Snapshots retain proposal provenance, protect against
  stale bases and support copy-on-rollback.
- Eval results record the actual overlay version/hash; judges resolve state from
  the variant's model, not whichever brain is configured globally.
- Requested/served model mismatches invalidate affected rows by default. Source
  recovery permits one retry, and fallback evidence is scoped to the case's run
  tree.
- Harness fixes cover BFCL inputs and tool expectations, gate-blocked calls,
  GAIA answer markers, `ask.user` transcripts, specialist TDD verification,
  council vote ordering and stub cleanup.
- Running presets expose detailed RAM, per-GPU VRAM and disk usage. Preset GPU
  attribution and disk-size reporting were corrected after live validation.

## Reliability, security and compatibility

- Dependency updates include LiteLLM 1.102.2, oauthlib 4.0.1, dnspython 2.9.2,
  filelock 4.2.1 and opentelemetry-api 1.45.2. Prisma is installed in the proxy
  environment so missing API keys return HTTP 401 rather than an error-handler
  HTTP 500.
- h5i 0.5.x and jevify 0.3 integrations are covered by compatibility tests.
  `code.deps`, file-type-aware linting, slash-spawned specialist sampling and
  strict-template fallback behavior received targeted fixes.
- `audio.speak` and persistent `doc.index` runs no longer inherit timeouts that
  cut off their expected cold-start or whole-document workloads.
- Admin, account, chat and login screenshots reflect preset priority, benchmark
  allowlists, versioned proposals, schedules and current model-server controls.

## Verification

The release gates cover the full Python test suite, Ruff, mypy, complexity,
prompt budgets, generated docs/rails, dependency audits, ShellCheck and diff
hygiene. Native Flash-Next delegation and brain restoration were also exercised
on the live two-GPU setup. Experimental engine benchmarks are not presented as
production-performance guarantees.

## Upgrading from v1.40.1

SQLite migrations are additive and automatic; the admin-managed preset catalog
and custom layer are preserved. Sync the main and proxy environments before
restarting; installations using the optional tool extras should sync that lock
too:

```bash
git fetch --tags
git checkout v1.50.0
uv pip install --python .venv/bin/python -r requirements.lock
uv pip install --python .venv/bin/python -r requirements-tools.lock
uv pip install --python litellmenv/bin/python -r requirements-litellm.lock
systemctl --user restart jaynet-web litellm-proxy
scripts/orch --doctor
```

Review **Admin → Models → Presets** after the upgrade because catalog order now
controls strength routing and local fallback. Natural memory recall is enabled
for explicit recall requests; automatic RAG and all Saber backends remain
opt-in. Existing model slots stay independent of the priority list.
