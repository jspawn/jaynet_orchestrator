# JayNet v1.44.0 — unified preset priority and safe failover

This feature release replaces static local-specialist fallback with one
ordered preset catalog. No database migration or manual priority setup is
required: existing catalog order is preserved until rows are reordered.

## Preset priority

Admin → Models → Presets is now a drag/drop priority list, with the top row at
priority 1. Strength requests try exact-tag holders in that order, then
`allround` holders. The first eligible `local-orchestrator` preset is the
universal final local fallback.

For example, if Saber is #3 and Turbo Coder #4 and both have `coding`, Saber
is primary and Turbo Coder is its coding fallback. Reordering does not change
**Boot model slots**, which still decide what starts. Priority is local to the
installation and is not exported in `.jaypack` files.

## Load and request failover

- Failed loads and generation probes restore evicted models before trying the
  next priority candidate.
- Request failover uses only allowlisted, payload-compatible presets whose
  live identity was verified. Backend/thinking behavior, think-strip family
  and vision compatibility must match.
- Presets sharing a public alias use exact `local-preset-<name>` deployments,
  retaining each preset's profile, overlay, context and capabilities.
- The generated static `local-specialist → local-orchestrator` fallback is
  removed. Cloud-provider fallback chains remain configured separately.

## Upgrading

Pull, restart JayNet and reload/restart LiteLLM so both the routing code and
generated proxy configuration use the new chains:

```bash
systemctl --user restart jaynet-web litellm-proxy
```

Then arrange presets under **Admin → Models → Presets**. Boot slots require no
changes.
