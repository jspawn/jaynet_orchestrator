# v1.6.0 — harness doctrine + one execution verb

2026-09-02 · Feature release with ONE breaking tool-surface change:
`code.execute` and `code.run` merged. Built from two full eval runs.

## Harness doctrine

"Route, don't do" is now enforced mechanically, not just prompted: a
per-run routing nudge fires right before the user turn on
coding/strength keywords (security cases get told which preset to
`model.use`), inline edits get a delegate gate, and `code.delegate`
children get a coding-sized default budget (24 iters) instead of the
fleet default 8. The gate prompt states the doctrine plainly.

## Features

- **Deliverable check** — the top tb failure mode (~half of all
  failures) was the agent solving the task and never calling
  `fs.write`. At the final answer, files the task or answer *named* but
  that don't exist in the workspace bounce the answer back once
  ("create it now"). `agent.deliverable_check.enabled`, default on.
- **Run delta** — Admin → Eval bulk run that skips cases that passed
  their last 3 runs, except a random 10% spot-check so silent
  regressions still surface. Explicit selections and scheduled suites
  always play what they named.
- **Wall-clock liveness extensions** — a run that hits its wall-clock
  cap mid-work gets short grace extensions (eval default 120 s × 5,
  chats off) as long as it keeps answering the iteration-boundary ping
  — zombie runs still die, slow finishers keep their work.
- **Tool-description overrides admin surface** (Admin → Tools →
  Description overrides): list/add/delete for the apply-target of
  accepted eval proposals; deleting restores the shipped description
  live; removed tools flagged "unknown tool" for pruning.

## Breaking: one execution verb

Every eval run that month needed a `code.*` fix; the two verbs differed
by intent, not capability, and small brains kept picking the wrong one.

- **`code.run` is now the one verb**: `command` + `language:
  bash|python`. The HARNESS picks the backend — eval case container →
  devbox → host firejail — the model never chooses a filesystem.
- **Container mode covers both languages** — in Terminal-Bench
  container cases code.run execs inside the task container too;
  absolute `/app/...` paths work from either verb. Case containers
  default to network ON (official TB posture; opt out per case with
  `container.network: false`).
- **`code.execute` stays as a visible legacy alias** (maps
  `code`→`command`, defaults to python) so saved chats, imported eval
  cases and older skills keep working. New prompts/skills say code.run.
- **Unified result contract**: status is `error` only when the tool
  itself couldn't run; a non-zero exit is `ok` + payload
  (`ok`/`exit_code`) — a failing test is not a tool error.
- **Eval-suite outage brake**: a run failing with backend ConnectError
  aborts the suite instead of burning the queue (a crash once poisoned
  74 cases in 1.4 s).

## Fixes (selection)

- Streaming model turns get the same malformed-tool-call-JSON nudged
  retry as non-streaming; the non-streaming retry no longer recurses
  inside the model semaphore (latent deadlock at concurrency 1).
- Routing-nudge security keywords cover intrusion/incident-response;
  short acronyms match on word boundaries ("source code" no longer
  triggers a spurious security nudge).
- Fictional-root fs rebase: `/app/...` paths from container task
  statements resolve onto the work_root instead of hard-failing.
- Eval robustness: crash rows persist, big seeds via stdin, userns
  work_root scrub, backend-outage grace probes, suite can't touch real
  systemd. Benchlab grades tb container cases via the task's own
  `run-tests.sh`. Devbox idle reaper actually runs.

- **D1** — `cloud_store.render` merges seed-only `litellm_params`
  (extra_body provider order, thinking, …) into rendered cloud entries
  — the OpenRouter upstream pin was dead config on every rendering
