# JayNet v1.40.1 — audit #33 follow-ups + dependency advisories

Patch release on v1.40.0, driven by the external audit of v1.40.0 and two
dependency advisories published after the tag.

## Dependency advisories

- **certifi** 2026.7.22 → 2026.10.19 in all three lockfiles
  (PYSEC-2026-4320 — the bundled CA store still trusted the emSign ECC
  Root CA - G3 intermediates with compromised keys; affects `web.fetch`,
  connectors, model/HF downloads).
- **pillow** 12.3.0 → 13.0.0 in the tools lock (8 CVEs: TIFF OOB reads,
  GIF/EPS decompression-bomb bypasses, PDF-append recursion,
  zero-width-image morphology).
- New local gate `scripts/check_dep_audit.sh` mirrors the CI pip-audit
  step for all three lockfiles, so advisories surface before the push.

## Build targets pinned

vllm, strata and radiance now build via `pin_repo` at reviewed commits
(`VLLM_COMMIT` / `STRATA_COMMIT` / `RADIANCE_COMMIT`) — the same pattern
the K2/Spark/Bonsai/Omni forks already used. `update` no longer pulls
single-maintainer upstream HEAD into a build that runs as the service
user next to models, data and API keys. llama.cpp deliberately keeps
tracking HEAD (main engine, closely followed, idempotent local patches).

## Smaller items

- **`/selftest` drops client auto-approve** — run scopes force
  `auto_confirm=False`, admins included: a self-test shows every
  confirmation-gated side effect instead of executing it silently
  (regression test included).
- **Fallback data dir is loud** — the web service warns prominently at
  startup when `JAYNET_DATA` is unset and it would boot on the
  `~/jaynet-data` fallback with fresh empty DBs.
- shellcheck `-S warning` fully clean, incl. a real shadowed `case`
  pattern in `prune-containers.sh` (`*llama*` also matched vllm/ollama
  images).

## Upgrading

Pull, restart. No migrations, no config changes. If you use
`build_tools.sh update`, the three new pins simply hold your trees at the
validated commits — bump them deliberately after reviewing upstream.
