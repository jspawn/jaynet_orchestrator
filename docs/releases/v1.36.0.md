# JayNet v1.36.0 — clearer Eval navigation and safer release cuts

## Eval admin reorganisation

The Eval console now separates running, monitoring, and detailed analysis:

- **Cases** opens with **Run** and **Scheduled runs**, followed by the case library.
- **Results** leads with **Statistics** and **Overall trend**, then the results ledger.
- **Result Details** is a new pill between Results and Proposals, grouping
  **Tool telemetry**, **Per case**, and **Period comparison**.

The screenshot sweep includes the new Result Details view and the refreshed
Cases, Results, and Proposals screens.

## Release-cut guard

`scripts/tag_release.py` now checks the exact committed `HEAD` before creating a
lightweight release tag. The runtime version, top CHANGELOG entry, and release
file heading must all match the requested `vX.Y.Z`; existing tags are refused.
Use `--check` for validation without tagging. The release test also requires a
matching current release record.

Historical mismatches at v1.20.8, v1.21.0, and v1.34.0 are documented in their
release files. Published tags were not moved.

## Admin-path and test-isolation fixes

All live references to the retired **Studio & Eval** admin tab were replaced,
including HTML-escaped text and the old Benchlab hash. The documentation gate
now rejects raw, escaped, and old-hash forms outside historical release notes.

Benchlab's Podman integration image tag is now process-unique, so concurrent
pytest runs cannot remove each other's image during teardown.

## Upgrade

No config or database migration is required. Hard-refresh the admin console once
(`admin.js?v=8`) and check that `/api/health` reports `1.36.0` after restart.
Future release tags should be created with `scripts/tag_release.py vX.Y.Z`.
