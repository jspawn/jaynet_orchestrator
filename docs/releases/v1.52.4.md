# JayNet v1.52.4 — upload, restore, and route availability fixes

This patch fixes route-level upload limits, attachment access, path
normalization, and event-loop blocking in admin and project operations.

## Uploads and attachments

- `/api/stt` now accepts the intended 25 MB audio file plus multipart overhead;
  the generic 4 MB middleware cap no longer rejects valid recordings first.
- `/api/v1/runs` adds the owner's upload directory to `extra_roots` whenever
  attachments are present, so `fs.*` and `code.run` can read them.
- Model deletion recomputes the normalized models-dir-relative path after
  `safe_join`, preventing redundant separators or dot segments from bypassing
  the active-preset guard.

## Availability and shutdown

- The eval scheduler loop is tracked by the normal background-task shutdown.
- Password verification and changes, process-log tail reads, and large
  project/scratch file writes run through `asyncio.to_thread`.
- Admin nested config updates replace YAML null intermediate values instead of
  crashing on `setdefault`.

## Streaming restore

Admin restore no longer buffers an archive of up to 1 GB into memory. Uploads
are capped while streaming to a temporary file in 1 MiB chunks; tar validation,
extraction, and whitelisted data-store copying run in a worker thread. The
existing traversal checks, store whitelist, WAL cleanup, and restart-required
response are unchanged.

## Verification

2,957 tests pass, including 5 MB STT uploads, v1 attachment-root checks,
normalized in-use model deletion, null nested config updates, and restore
round-trips. All release gates pass.

## Upgrading from v1.52.3

No dependency or database migration is required:

```bash
git fetch --tags
git checkout v1.52.4
systemctl --user restart jaynet-web
scripts/orch --doctor
```
