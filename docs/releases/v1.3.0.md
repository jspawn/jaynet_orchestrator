# v1.3.0 — plugins that travel, knowledge that connects, projects born with a charter

2026-08-23 · Feature release. Three threads: the plugin system grows its
last mile (distribution, live toggling, admin UIs), the knowledge surfaces
start talking to each other, and new projects can be born with a charter.
No breaking changes.

## Highlights

- **`.jayplugin` packaging** — export any plugin from Admin → Plugins,
  install it on another JayNet with one upload (same guards as `.jaypack`).
  `plugin.yaml` gains honest requirements: `requires_bins` (executables,
  reported but never blocking) next to pip `dependencies`; the Plugins tab
  renders each plugin's README and declared deps.
- **Plugin hot-reload** — toggling in Admin → Plugins applies **live**:
  tools, hooks, skills, routes and admin UIs register/unregister in-process
  (new runs only; in-flight runs keep their frozen toolset). Fresh
  `.jayplugin` installs get a **load now** button. A restart is only needed
  for newly installed pip dependencies. Lifecycle hooks
  (`startup_hooks`/`shutdown_hooks`) run on hot toggles too — startup on
  enable, shutdown before anything is unregistered.
- **Plugin admin UIs** — a plugin may ship a static `ui/` dir, served
  admin-gated inside the Plugins tab (iframe panel, not a new window).
  benchlab ships the reference UI with live job polling. New builtin skill
  **`plugin-authoring`** guides building your own, end to end.
- **Wiki pages as graph nodes** (graphify, default on) — a deterministic
  extractor appends one node per project-wiki page plus `references` edges
  from markdown links, before clustering, so pages get communities and land
  in report/viz. Opt-out: `plugins.graphify.wiki_nodes: false`.
- **Knowledge-surface bridge** — `graph.seed_kg` seeds a project graph into
  the curated kg with provenance attrs (merge-on-reseed,
  confirmation-gated), and project-bound `rag.search` now carries a
  `graph_excerpt`: the 1-hop project-graph neighborhood around its hits.
- **Graphify auto-rebuild** (opt-in) — file changes (web edits AND the
  agent's own `fs.*` writes) re-arm a debounced rebuild for projects that
  already have a graph. Off by default — the semantic pass is the expensive
  part; having built once is the consent gate.
- **Project charter interview** — creating a project offers a charter
  interview (or plain start). The agent asks one question at a time with
  recommended answers (grilling doctrine) and compiles the answers into the
  project wiki's first pages — `overview`, `goals`, `constraints`,
  `glossary`, `decisions` — which the wiki extractor then carries into the
  project graph. Also available anytime via `/charter`.
- **Hardened after audit** — the `rag_excerpt` hook caches the parsed
  graph.json by (mtime, size) instead of re-parsing per request; hot
  toggles invalidate the cached OpenAPI schema so `/docs` stays honest;
  `.jayplugin` installs validate the inner manifest at upload time.

## Upgrade

Pull, restart, done. Everything new is opt-in or defaults-safe; nothing to
migrate. Auto-rebuild stays off until you flip
`plugins.graphify.auto_rebuild: true`.
