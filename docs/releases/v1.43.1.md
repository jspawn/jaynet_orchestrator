# JayNet v1.43.1 — routing and admin hardening

This patch release fixes audit #35 findings and includes the two post-v1.43.0
admin improvements. No dependency, database or configuration migration is
required.

## Plan-gate routing

- Read-only questions, reviews, summaries, documentation requests and prose no
  longer trigger an automatic architect run merely by mentioning migrations,
  features, design documents or multi-file diffs.
- Generic automatic planning requires technical context, so requests such as
  planning a birthday party stay on the normal chat path.
- Complex implementation patterns now require an implementation verb. Explicit
  plan mode is unchanged, and destructive production or migration actions still
  receive mandatory planning even in direct mode.

## jevify administration

- The plugin UI can select an active local preset, verify the served model,
  probe its recipe and restart only the managed jevify sidecar.
- Configuration requests that overlap across the request-body await now fail
  immediately with HTTP 409 instead of serializing and restarting the sidecar a
  second time.

## Model downloads and verification

- “Create preset” from a Hugging Face download now loads the catalog and opens
  the preset editor in Models → Presets.
- Removed the literal admin cache-buster assertion; the fallback-warning test
  now checks behavior rather than requiring a test edit on every JS bump.
- Full verification: **2,810 tests passed**, with Ruff, complexity, mypy,
  generated docs, prompt budgets, shellcheck and all dependency audits clean.
- Screenshots were not refreshed for this release because both live services
  were stopped during the audit fixes.

## Upgrading

Pull this release and restart the web service. No dependency update is needed:

```bash
systemctl --user restart jaynet-web
```
