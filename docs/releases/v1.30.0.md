# JayNet v1.30.0 — measured tool trim, BFCL v4, office files fixed

A measurement-driven release: the always-on tool prefix shrank 30% and
was validated with a proper A/B, the Berkeley Function Calling
Leaderboard landed as a permanent regression net, and the office-file
skills work out of the box again. 2,400+ tests green; all gates clean.

## Core toolset trim (measured, A/B-validated)

The always-on tool prefix dropped 18 → 13 tools (~4,470 → ~3,145 schema
tokens, −30% on every turn). Evicted by tool-value data over 3.9k traced
runs (schema cost vs actual use): `agent.spawn`, `fs.find`, `context.pin`,
`gpu.status`, `memory.get` — all five stay reachable via keyword routing
or `tools.load`. The delta eval against a frozen baseline: 5 fail→pass /
2 pass→fail flips, McNemar p=0.45 — no regression, and `agent-fanout`
improved reproducibly.

## BFCL v4 + stub-tool eval cases

The eval case format grows `stub_tools` (case-declared function schemas
registered as recording stubs — the run sees exactly those tools),
`expect.tool_calls` (BFCL AST-style argument grading), and `judge: false`
(deterministic-only verdicts, zero judge spend). Benchlab imports BFCL v4
as a third source: 8 single-turn categories, ~120 cases, tag `bfcl`.
First clean numbers on the local brain: ~92/120 (76.7%) — simple 15/15,
parallel_multiple 14/15, irrelevance 14/15. Two harness-fidelity fixes it
immediately earned: stub payloads that don't invite retry loops, and
first-turn-only grading (BFCL is a single-turn protocol).

## Office-file creation works out of the box

The devbox image ships python-docx/openpyxl/pptx (rebuild with
`scripts/devbox-build.sh`), so the docx/xlsx/pptx skills run with bare
`python3` via `code.check` — no venv, no network. The skills now lead
with that path and say plainly: never write your own converter. Related:
`fs.*` on a skill file no longer returns a bare "outside your workspace"
refusal — it tells the agent to RUN the script instead (the old message
is what sent the brain off hand-coding a converter). The devbox
Containerfile also wires the .NET backports PPA manually —
`add-apt-repository` can't reach Launchpad from container networks.

## Admin: config editor honesty

Harness → Runtime hid ~50 dead-end rows: `models.presets*/gpus/binaries`
are DB-seeded (edits silently did nothing), `boot`/`default_posture`/
`processes.*` are boot-only, strengths live in Models → Strengths. What
remains is "Model Swapping": the two live-effective scheduler flags with
a pointer to Admin → Models.

## Upgrade notes

  office libraries — until then the skills fall back to the venv route.
- BFCL cases: Admin → Studio & Eval → Benchlab → "Import BFCL v4", then

- If you overrode any now-hidden config keys (`models.*` seeds,
  `processes.*`), the overrides still apply — they're just no longer
