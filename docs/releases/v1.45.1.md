# JayNet v1.45.1 — reliable Flash-Next delegation

This patch release makes managed Saber Flash-Next work through complete coding
delegations and keeps specialist children attached to the parent's workspace,
stores and sandbox.

## Flash-Next compatibility

- Native launch handling accepts the checkpoint's quantization metadata and
  declared PLE/vision exclusions, and raises the file-descriptor limit.
- Strict chat templates receive one leading system message and defined content
  on every turn, including tool-only assistant turns.
- Verified live: Occamy delegated a CSV implementation to Qwen3.8 Flash-Next
  TP2, the specialist wrote and tested it successfully, and Occamy was restored
  healthy afterward.

## Delegation continuity

- Ordinary specialist children share the parent's effective workspace. This
  fixes scratch-only runs where the parent could not see or reuse the child's
  deliverables. Explicit `isolated=true` worktrees remain separate.
- Children inherit run-scoped store and sandbox redirections, including eval
  memory/RAG databases, Graphify project directories and container routing.
- Coding and research specialists can use read-only `memory.search`, `kg.query`,
  `kg.neighbors`, `graph.query`, `graph.explain` and `rag.search`. The parent's
  allowed-tool set still narrows these capabilities.

## Verification

- **2,847 tests passed**, including workspace, context-tool and override
  inheritance regressions.
- Ruff and diff checks pass.
- The complete live GPU delegation and brain-restoration test passed.

## Upgrading

Pull and restart both services:

```bash
systemctl --user restart jaynet-web litellm-proxy
```

Existing presets and stores need no migration.
