# v1.1.1 — Hardening + MCP server manager

2026-08-20 · The 1.1.0 plugin drop gets its audit follow-ups (two real bugs
fixed), and MCP servers move out of raw-YAML-only editing into a proper
admin UI.

## Highlights

- **Plugin audit fixes.** The graphify plugin's build runner was imported
  three times under different module names — three independent job
  registries. In practice: starting a build from the chat UI *and* via the
  agent's `graph.build` spawned two concurrent builds into the same output
  dir, and deleting a project never cancelled its running build. All entry
  points now share one cached module, with a regression test. Staleness
  marking also ignored a custom `web.projects_dir` — fixed by passing the
  resolved root into the hook (signature change, see below).
- **Admin → Tools → MCP servers.** MCP servers were YAML-only and invisible
  in the admin UI — an empty `servers: {}` flattens to nothing in the
  Config editor, so there was literally nothing to find. Now there's a
  proper manager: add/edit/delete stdio or HTTP servers, confirm-per-call
  toggle, per-server timeout, and a Test button that connects and lists the
  server's tools. Saves apply live, no restart.
- **`project_tools` plugin hook.** Plugins can declare tools a project-bound
  run must keep reachable; graphify uses it so its "prefer graph.query"
  prompt hint can never advertise tools the frozen toolset doesn't include.
- **New doc: `docs/playbook.md`** — the whole tool/skill/chain/plugin
  landscape in prose, ending in an honest verdict.

## Also in this release

- Plugin loader survives a malformed `plugins:` config block instead of
  crashing at boot; malformed dependency names mark the plugin unavailable
  instead of raising.
- Graphify `status.json` writes are atomic (temp + rename); finished build
  jobs are pruned from the registry.
- `docs/security.md` documents the plugin trust surface (in-process Python,
  no sandbox) and the graphify semantic pass as config-gated egress.
- Plugin author docs warn that every `exec_module` creates fresh module
  state — the pattern behind the runner bug was previously the *documented*
  way to share code between plugin files.
- `label_communities` graphify knob is now seeded in runtime.yaml + inline
  config help.

## Breaking

- The `on_project_file_changed` plugin hook signature changed from
  `(owner, pid, path)` to `(owner, pid, path, projects_dir)`. Only relevant
  if you wrote a 1.1.0 plugin against it — update the signature and use the
  passed root instead of deriving your own.

## Upgrade

Pull, restart, done. Nothing changes for instances without plugins or MCP
servers configured.
