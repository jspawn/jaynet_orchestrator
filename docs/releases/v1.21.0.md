## procedure.save / procedure.run / procedure.list

When a task boils down to deterministic logic (a formula, a conversion,
a fixed check pipeline), the model writes it ONCE as a small python or
bash script, saved into the run's workspace under `procedures/` with a
JSON description sidecar. Later runs re-execute it with new inputs via
`procedure.run` — zero model tokens, byte-identical logic, inspectable
and editable as plain project files.

- Inputs ride as the `ARGS` dict (python) or `$PROC_ARGS` JSON (bash);
  the script's printed output is the result.
- Execution rides the code.check engine: sandboxed, network off, 120s
  cap; a non-zero exit is a normal result, not a tool error.
- Files are plain text — rename/edit/delete with the fs.* tools;
  procedure.* is the disciplined front door. `procedure.list` shows
  what's already scripted before re-deriving logic.

Authorship vs reuse: the coding specialist authors via procedure.save;
the brain's steady-state move is procedure.run.
