# v1.20.0 — 2026-10-05

Patch-plus release: the first **live** `model.measure` round exposed two
launch-path bugs the test fakes never told, plus the docs catch-up for
everything shipped in v1.18.4–v1.19.0 and a new live-ops script.

## Live-found fixes

**Materialized confs now carry the catalog slot.** `serve.start`
*requests* a port, but the dispatcher's `--preset` file mode lets the
`.conf` own the slot — and the materialized confs carried no `PORT`, so
the measurement server quietly bound the `:8080` default while the
ready-wait polled the requested catalog port for 600 s. Materialized
confs now get the catalog's `PORT` / `VISIBLE_DEVICES` appended;
name-mode PM boots capture and ignore those keys, so regular model
booting is unchanged.

**Readiness parses both `/v1/models` wire shapes.** Some llama.cpp
builds answer in the legacy `{"models": […]}` shape instead of OpenAI
`{"data": […]}` — a probe that only reads `data` never sees the model
ready. `query_model_ids` now parses both (and still raises
`EndpointAuth` on 401/403).

The hibernate → restore path validated itself live: the failed
measurement still brought brain and specialist back on its own —
restore-what-was-probed, measurement server down first, even on error.

## `scripts/slash-run.py`

New live-ops driver: fires any slash command at `/api/chat`, streams
`/api/stream/{id}`, **auto-approves confirmation prompts** (a 30-minute
`model.measure` would die on the 300 s confirm timeout otherwise), and
prints the final answer. Same discipline as `eval-peek.py` /
`eval-delta.sh`: drive the live API, never the live checkout.

```bash
scripts/slash-run.py "/model.measure preset=cybertiel-35b-a3b"
```
