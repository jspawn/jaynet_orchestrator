# v1.20.3 — 2026-10-06

Doc/quality audit S-batch (items #2, #4, #12, #14, #15) — docs
infrastructure and freshness gates. No runtime behavior change except
one config cleanup (dead `studio.python` entry removed).

## "Life of a turn" + the rail registry

The loop's guard stack was only discoverable by reading
`runtime/loop.py`. Now:

- `docs/turn.md` — the exact execution order of one iteration:
  compaction → pre-turn guards → model turn → (tool path: inline
  tool-call gates → execute → post-tool guards) / (final path:
  final-answer guards → bounce cap → verifier), as a mermaid
  flowchart with the load-bearing order notes.
- `docs/rails.md` — the generated registry of every guard and
  dispatch gate: name, order, purpose, config keys/defaults, and the
  live case that motivated it. Generated by `scripts/gen_rails.py`
  from the actual registries — a rail missing from the metadata table
  is a build error, and renamed dispatch gates break the build via
  source anchors. CI checks freshness (`--check`).

## Complexity ceiling for new code

`scripts/check_complexity.py` enforces ruff C901 at a ceiling of 25
with a committed baseline (`tests/complexity-baseline.txt`, 18
grandfathered hotspots). NEW violations fail; a grandfathered
function growing MORE complex also fails; shrinking always passes and
`--write` banks it — the same mechanism as the mypy baseline. CI ruff
now covers `plugins/` as well.

## Docs index by audience + freshness checks

- `docs/README.md` routes readers — chat user, operator, contributor,
  AI session — to the right docs; every doc carries a one-line
  audience header under its title.
- The README's "Example setup (wolf)" section moved to
  `docs/my-setup.md`, clearly marked example-only (bakeoff/llama-ops
  numbers are measured on that box).
- `scripts/check_doc_tools.py` scans all docs for dotted tool names
  and fails on any that don't exist in the registry (config-key and
  record-field lookalikes filtered, small hand-reviewed skip list).
  It caught two real oddities on its first run.

## Config cleanup

`studio.python` in `security.admin_only_tools` matched no tool —
Studio custom tools register under the `custom.*` namespace, and the
entry dated from the original role-policy commit. Removed from the
shipped config and the security doc, which now states the actual
posture: custom tools are arbitrary Python, but authoring is
admin-gated (`/api/admin/studio`), so at runtime they are as trusted
as any built-in and stay invocable by all accounts.
