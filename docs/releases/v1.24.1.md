# v1.24.1 — final-verdict fixes: account deletion, auth hardening

Patch on 1.24.0 from the 2026-10-12 final audit (verdict: ledger clear,
no high-severity; this patch closes its two mediums and five lows).
2,355 tests green; all gates clean, including the baseline-bump marker
rule on the complexity gate.

## Deleting a user now deletes their state (medium #1)

`admin_delete_user` used to leave the account's scheduled runs firing and
its owner-scoped knowledge (memory, kg, rag, pageindex) and trace history
in place — and because new accounts started at `session_epoch` 0, a
recreated same-name account validated the deleted account's unexpired
cookies. Now: delete removes schedules + knowledge rows + trace runs
(best-effort per store, counted in the response; folders stay reported as
`leftover_paths` for manual cleanup), new accounts start at a random
epoch, and the scheduler skips entries whose owner no longer exists
(backstop for pre-fix rows).

## Dispatch prompt follows the gate (medium #2)

The lean dispatch prompt was picked once at boot while the dispatch gate
re-evaluates per run — a live slot move to a non-coding preset (or a
config flip in the editor) could split them. Both prompts load at init
and `_system_prompt` picks per run with the gate's own predicate; a test
flips the specialist slot mid-session and watches the prompt follow.

## Auth hardening (lows #3, #7)

- The login throttle keys on username+client IP (X-Forwarded-For trusted
  only from the configured proxy), so a stranger can no longer keep a
  known account locked out.
- TOTP codes are single-use within their window — the matched timestep is
  claimed atomically (`users.totp_last_counter`), replays rejected.

## Smaller lows (#4–#6)

- The red→green tree-snapshot failure no longer falls back to HEAD
  silently (the wrong baseline fixed last round) — discrimination is
  marked unverifiable instead.
- The tool-tier completeness sweep follows in-repo imports one level
  deep; 14 tools that spawn through shared helpers (git remote verbs,
  code.check, agent.spawn/fanout, …) are now classified with reasons.
- Every harness git call runs with `core.hooksPath=/dev/null` and
  fsmonitor off (`GIT_SAFE_FLAGS`) — a writable `.git/config` can't turn
  a JayNet git read into an exec.

## Test-suite hygiene

A redundancy sweep (automated checks over all 2,360 tests + ~190
cross-reads) found the suite healthy — no dead targets, no duplicate
parametrizations — and deleted 5 verified-redundant tests (one
byte-identical duplicate, one subsumed, one same-path twin, two
can't-fail tests that asserted on their own hand-computed dicts). Also
fixed: the conftest data-dir pin was not idempotent under pytest-xdist's
double conftest import (env var and `runtime.paths` could disagree
worker-wide).
