# v1.20.7 — Overlay drift warning + guard telemetry

Patch release on 1.20.6. Admin-surface hardening only — no
model-behavior changes, no config migration. 2,279 tests green; all
gates clean.

## Prompt overlay drift warning

The custom overlay (`$ORCH_DATA/custom/`) wins over the shipped prompt
whenever it exists — which means it **silently shadows every shipped
prompt change**. It already bit once: a Sep-28 overlay ran stale
through weeks of delta evals while shipped fixes piled up underneath.

Now, for the gate prompt and every worker-prompt part:

- `gate_prompt.staleness()` / `worker_prompt`'s `parts()` and
  `describe()` flag an overlay whose mtime predates the shipped file
  (a deploy pulled newer defaults after the overlay was last saved).
- `load()` logs a boot warning when serving a stale overlay.
- `GET /api/admin/prompt` carries `stale` + both mtimes.
- Admin → Harness → Prompts shows a warnbox ("review, re-save to keep,
  or revert to shipped"); stale worker parts get a ⚠ in the dropdown
  and the same warnbox in the editor.

## Guard telemetry in eval-peek

`guard_fired` events have been emitted since the guard-registry work
but nothing read them (claude audit 2026-10-06 #6). Every
`scripts/eval-peek.py` report now closes with a per-guard table:

```
guards: fire rate | pass rate fired vs quiet:
  stall_check      4/5 (80%)  fired-pass  75%  quiet-pass   0%
  just_reply       1/5 (20%)  fired-pass   0%  quiet-pass  75%
```

A rail whose pass-after-fire is ~0 only fires on doomed runs — that's
the ablation candidate list. The first `guards_off` ablation can now
be data-driven instead of a guess.

## Upgrade

Pull, restart. If Admin → Harness → Prompts shows the stale warnbox
after the pull: that's the feature working — your overlay predates the
shipped prompt; review the diff and re-save or revert.
