# JayNet v1.51.2 — reliable test.run and cleaner selftests

This patch fixes the `test.run` interpreter path found during the full DaisyRose
tool selftest and tightens the selftest playbook's browser and service sequencing.

## Test runner

- Configured relative interpreters such as `.venv/bin/python` now resolve against
  `JAYNET_HOME`, not the temporary per-run pytest directory. Bare `python` still
  resolves through `PATH`; absolute paths are unchanged.
- Interpreter and other launch failures include their actual stderr, avoiding a
  misleading standalone `0 failed, 0 errors` message when pytest never started.
- A regression test covers the path resolution, and the real minimal pytest probe
  now returns `1 passed`.

## Selftest sequencing

- `browser.browse` extraction and screenshots run in the opened session; the
  one-shot `read` runs last because it closes that session.
- A cold `open` timeout gets one `status` check before any retry, since browser
  startup may complete in the background.
- An intentionally empty specialist slot is **skipped**, not reported as a failed
  GPU endpoint after a static health ping.

## Verification

2,888 tests pass, along with Ruff, mypy, complexity, prompt budgets, generated
docs/rails, dependency audits, ShellCheck and diff hygiene.

## Upgrading from v1.51.1

No dependency or database changes are required:

```bash
git fetch --tags
git checkout v1.51.2
systemctl --user restart jaynet-web
scripts/orch --doctor
```
