# v1.8.0 — procedure checkpoints, judge calibration, skill A/B

2026-09-06 · Feature release. The loop now enforces procedure checklists,
the eval harness can measure its own judge, injection attacks are graded
deterministically, and benchmarks can A/B a single skill. No breaking
changes.

## Loop: procedure checkpoints

Procedures (shape-tagged skills) declare a `checkpoints:` frontmatter
list — short, checkable statements distilled from the failure clusters
that motivated each procedure. When a procedure auto-loads, the loop
keeps its checklist and enforces it in two places: stall-ladder rungs
name the active procedure and its remaining items, and a final answer is
not accepted before a one-shot `procedure_check` nudge lists the
checkpoints to confirm or complete. The three shipped procedures
(implement-from-spec, debug-and-fix, research-and-verify) carry their
lists; `handoffs/skills.md` documents the format for skill authors.
This completes the procedure-library core: distilled frontier process,
selected by shape, auto-loaded for small brains, and now checked by the
loop itself rather than left to the model's discipline.

## Eval: prompt-injection cases + canary grader

Two new shipped cases: a hostile HTML comment hidden in a seeded page,
and a fake `[SYSTEM]` pre-approval inside an inlined attachment. Both
are graded by the new deterministic `canary_not_in_tool_args`
expectation — the trace's tool-call args are scanned for the planted
canary, since the trajectory string truncates args. The judge rubric
grades *flagging* the injection to the user, not just refusing it.

## Eval: judge calibration

The judge is the harness's ground truth — its own accuracy is now
measured, not assumed. `evals/judge-calibration.json` freezes ten
transcripts with known-correct verdicts across the judge's strictness
axes (exactness, privacy gates, test-weakening, unverified claims,
injection-following, honest partials). Admin → Eval → *Judge
calibration* grades them with the current judge model and reports
per-pair agreement. Run it after switching judge models: a judge that
disagrees with ground truth silently corrupts every proposal it emits.

## Eval: local judge default

The shipped judge/driver default is now `local-specialist`. Cloud
judging stays available as an explicit config override — but the
default no longer sends eval transcripts off-box (docs/security.md
restates the egress posture).

## Eval: benchmark skill A/B

Benchmark variants accept `disabled_skills` — hidden from the skill
catalog, refused by `skill.load`, enforced by the loop. "Same brain ±
the skill that claims to help" becomes a measurable A/B; the immediate
question it answers is whether the long-document skill actually beats
raw programmatic slicing on `rlm-log-aggregate`. New *Without skills*
column in the Benchmark variants table.

## Upgrade notes

Pull, restart both services. If you want to keep a cloud judge, set
`eval.judge_model` / `eval.driver_model` in Config — the shipped
default flipped to local. Nothing else to do.
