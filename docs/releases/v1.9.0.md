# v1.9.0 — hardware-wide swaps + swap-back

2026-09-10 · The multi-GPU lifecycle release: any model can claim any
subset of the machine's cards, and delegate swaps put everything back.

## Swap planner (from port-scoped to hardware-wide)

`model.use(preset, swap: true)` used to free only the model sitting on the
target port. Now an eviction planner
(`tools/model/catalog.py: plan_eviction / evict_records / restore_evicted`)
computes what the incoming preset actually needs — its port **and every
pinned GPU** — and stops the whole set:

- serve-registry models via `serve.stop`, boot-posture slots via the
  process manager (`stop_one`, so auto-restart stays disarmed mid-swap);
- systemd units and remote (LAN) presets are never touched;
- after each stop JayNet waits for the port to close **and** the VRAM to
  be released on every affected card before loading — a follow-up load on
  a half-freed card used to OOM;
- a swap that cannot free its hardware refuses to load and names the
  blocker, instead of dying inside llama-server.

The `evicted` list in the model.use result says exactly what was stopped.

## Swap-back: the brain comes back by itself

When `code.delegate` swaps in a strength-tagged specialist whose GPUs the
brain occupies (the big-brain-across-both-cards layout), it passes
`include_brain: true` and — once the child run finishes, fails, or raises —
**restores the evicted set**, brain first, waiting until each model answers
on its own port again. Boot-posture slots restart through the process
manager; serve-managed models re-serve via model.use; a slot that was
running a non-default preset is restored to *what was actually live*, not
the boot default.

Config: `models.swap_back: true` (default). Restore failures are spelled
out in the delegate result and visible in Admin → Processes. Direct
`model.use` swaps still refuse to evict the brain — only delegate's
restore-covered path may.

## Preset editor: standard / all / raw

- **Standard view** (default): model file, ctx size, GPU layers, temp —
  plus split mode / tensor split the moment the device picker spans more
  than one card.
- **All launch options** unfolds the full structured form; **advanced
  (raw .conf)** is unchanged. Switching views never drops a stored value.
- The device dropdown is now a **checkbox per GPU** — any subset (`0,2`),
  all cards, or CPU — and each GPU row shows the card's **live free VRAM**.

## Platform fixes

- VRAM probing falls back to **nvidia-smi** when rocm-smi is absent — CUDA
  boxes get real headroom checks instead of silently skipping them
  (runtime/serving.py `read_vram` / `gpus_free_gib`).
- Launches honor the preset binary's `device_env` (CUDA_VISIBLE_DEVICES,
  GGML_VK_VISIBLE_DEVICES, …) instead of a hardcoded HIP_VISIBLE_DEVICES.

## Upgrade note

No migration needed; preset DBs with a comma `gpu` already loaded
multi-card — this release makes the rest of the stack understand them.
If you previously worked around port-scoped swaps (manual Processes-tab
stops), plain `model.use(..., swap: true)` now covers it.
