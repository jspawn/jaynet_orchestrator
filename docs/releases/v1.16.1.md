# v1.16.1 — 2026-10-01

Patch release: audit #26 (report-only audit of the h5i red-team browser,
the 6-tab admin console, and the graceful-endings work) found one C — the
new `on_run_end` plugin hook blocked the event loop — plus a trail of
retired-tab references, an update-check contract that didn't match its own
behavior, and a path-injection-shaped hardening gap in the h5i screenshot
verb. All fixed, with two new static gates so the classes stay closed.

## The one C

- **`on_run_end` no longer blocks the event loop.** The hook fires per run
  at finish; the shipped h5i handler runs a blocking `h5i browser close`
  subprocess (up to 10s) — on the loop thread of a one-process uvicorn
  service, that froze every other run's token stream and every web request.
  The loop now fires through `asyncio.to_thread`, fixing it for every
  present and future plugin. The payload also carries a `config` snapshot,
  and the h5i session reaper resolves `plugins.h5i.binary` first — on a
  non-PATH install the reaper silently never ran, recreating the stale-
  session pile-up it exists to prevent.

## Fixes and hardening

- **Retired tab names swept (107 references).** The 16→6 admin reorg left
  pointers to tabs that no longer exist in user-visible places: config
  comments and `config-help.yaml` strings (rendered in the Runtime editor),
  model-facing tool notes, skills loaded into prompts, handoffs, and the
  Presets help text inside admin.html itself. Everything now uses the new
  paths (Models → Servers/Presets, Harness → …, Studio & Eval,
  Status & Usage).
- **Update check contract tells the truth.** Config/help claimed outbound
  calls happen "only when an admin clicks Check now"; the card auto-loads
  with the console. Texts corrected to: probes fire when an admin opens the
  Status page (cached 24h), Check now forces a fresh one. `updates.enabled`
  help moved out of the council block; the delegate-cap help's stale
  "fleet-wide 8" corrected to 16.
- **h5i screenshot path clamp.** The `--out` path was built from the raw
  model-supplied session name — a traversal-shaped value would have landed
  the PNG outside the scratch dir. Clamped to a safe filename; the
  `mkdtemp()` fallback (leaked a directory per call) is `gettempdir()`.
- **Version-compare shape guard.** `_status` degrades to `unknown` when the
  installed and upstream tag shapes differ (e.g. `(11280,)` vs `(0,5,0)`)
  instead of comparing — the silent inversion behind "current while 40
  builds behind".
- **h5i CLI `--` separators.** Model-supplied ids/urls reach the h5i CLI
  only after `--`, so a value shaped like a flag can't inject into h5i's
  own parser (verified against the installed binary: it lands in the id
  slot and fails as a bad id).
- **Small stuff:** the chat lightbox's Esc listener is removed on every
  close path; `TurnModel.time` gets the same capping validator as `atts`;
  `check_updates()`'s dead `config` parameter dropped.

## New static gates

- Every literal `$("#id")`/`getElementById` in admin.html must resolve to a
  markup id, and every TABMAP pane/sub target must exist — the admin
  reorg's load-bearing contract, pinned for future reorgs.
- Every `screenshots/*.png` a doc references must exist — screenshot-sweep
  renames can no longer 404 a doc image silently.

Also in this cut: `__version__` now bumped in the release commit (the
v1.16.0 cut missed it; the tag was re-pointed before ever being pushed).
