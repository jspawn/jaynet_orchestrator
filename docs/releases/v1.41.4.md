# JayNet v1.41.4 — audit #34 follow-ups

This patch closes the two code findings from audit #34 and refreshes the
associated documentation.

## Reliable brain-overlay writes

- `BrainOverlayStore.apply()` and `rollback()` now use `BEGIN IMMEDIATE` before
  reading the active snapshot or allocating a version.
- Concurrent accepts can no longer race into uniqueness-constraint HTTP 500s or
  append a successor that silently drops another accepted lesson.
- A competing proposal now receives the intended stale-base response; retrying
  the same proposal remains idempotent. Regression coverage forces the old race.

## Cross-model eval state

- Judge state and result provenance now resolve the overlay from the variant's
  actual model instead of the configured brain.
- Cloud and benchmark arms therefore no longer record or get judged against
  prompt, skill, tool and config text they never received.

## Documentation and checks

- Refreshed `admin-schedules.png` with the observe-only arXiv controls and
  `admin-models-servers.png` with process usage controls.
- Updated the scheduler implementation references, process-usage code map and
  Schedules caption. Banked the eight-line mypy baseline shrink.

## Verification

**2,745 tests pass**, along with Ruff, complexity, mypy, prompt/documentation
checks, dependency audits, ShellCheck and release-metadata checks.

## Upgrading

Pull and restart JayNet. No configuration or database action is required.
