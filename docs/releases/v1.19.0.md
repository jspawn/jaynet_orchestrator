# v1.19.0 — 2026-10-05

Feature release: presets carry **measured** memory usage, and the model
loader schedules by fit instead of treating any co-tenant as a conflict.

## Preset-measured memory scheduling

Until now `vram_gib` was a hand estimate, and the eviction planner
treated *any* running model on a pinned GPU as a conflict — a specialist
using 50% of GPU1 blocked a second model that would have fit fine.

**`model.measure(preset)`** (confirmation-gated, disruptive) closes the
measurement gap: it hibernates the whole box — brain included, via the
existing eviction machinery — loads the preset alone, waits ready, fires
one tiny probe completion, and diffs per-GPU VRAM and system RAM
before/after. llama.cpp preallocates weights + full-context KV at
startup, so one probe captures the real footprint. The result is written
into the preset as `measured` JSON (per-card GiB, total, RAM, ctx,
timestamp) — a new presets.db column with migration, round-tripping
through preset export/import. Whatever was running before is restored
afterwards, even on cancel.

**The loader schedules by fit.** With a current measurement (same ctx,
same GPU pinning), a new model loads **alongside** existing tenants when
every pinned card has `free ≥ measured_share + floor` — no swap, both
run. Eviction happens only on a genuine shortfall on a shared card, or a
port conflict (always). CPU presets get the same rule against
`MemAvailable` (`models.min_free_ram_gib`, default 2.0). Stale
measurements (preset edited since) fall back to the `vram_gib` estimate
split evenly; unknown needs stay conservative (today's behavior).

Imagegen keeps its free-all-and-try posture — its usage depends on the
image size, so measuring wouldn't help there.

## Upgrade

Pull, restart `jaynet-web`; the presets.db migration runs on first
start. Then measure your active local presets once (idle box):
`model.measure` for brain, specialist, embed, rerank — a few minutes
each, confirmation-gated since it hibernates everything. Re-measure
after changing a preset's ctx or GPU pinning. New config keys (both
additive with safe defaults): `models.min_free_ram_gib: 2.0` and
`call_timeout_overrides` entry `model.measure: 1800`.
