# v1.18.0 — 2026-10-04

Minor release: the brain learns to pace itself. One line of context —
`budget: iteration 3/8`, re-injected every turn — closes a whole class of
eval flakes where the agent over-verified trivial answers and over-searched
because it could not see the budget it was spending against. Plus: evals
now enforce their declared iteration caps instead of scolding afterwards,
a reusable two-arm A/B driver, and the result of the CLM state-file
experiment (tested, measured, parked).

## Per-turn budget visibility (`agent.anchor.budget`, default on)

Every model turn ends with a one-line readout at the prompt tail:
`budget: iteration 3/8` (used/limit; just the used count when uncapped).
It rides inside the working anchor when `agent.anchor.mode` is on and
stands alone at the todos re-injection slot otherwise — rebuilt per turn,
never persisted into the transcript, so it survives compaction by
construction. Delegated specialists see their *own* child budget the same
way (they run through the same loop path).

The motivation was a recurring flake class: the brain would call
`code.check` five times to verify a date it already knew, or burn 15
iterations searching before asking the user — then the judge failed it for
exceeding a cap it never saw. With scarcity visible, the flakes
disappeared: the targeted set (datetime-awareness, fs-roundtrip, ask-user,
j-space-loop, budget-clean-exit) went **5/5** on the first post-fix delta.
`agent.anchor.budget: false` = zero injection.

## j-space badge gate (`loop_guard.jspace_badge_gate`, default on)

The 3× repeat then told the truth the 5/5 hid: budget visibility fixed
*pacing* but not *protocol compliance* — j-space-loop failed 3/3 on a sole
deterministic check (`run.badge` never called; the rename, plan and tests
were all done right). So protocol gets a hard gate, same shape as the
dispatch gate: once the j-space skill is loaded, `fs.write`/`fs.edit` on
paths outside `.jspace/` are rejected at dispatch (never executed) until
`run.badge` was called. The rejection names the exact recovery (classify
fast/full/loop, badge, re-issue), the `.jspace/` ledger flow stays
writable, the gate opens permanently after the first badge, and rejections
count toward `loop_guard.max_rejections` so a refusal ends in the standard
wrap-up instead of spinning to the cap.

## Evals enforce their stated iteration budget

A case's declared `expect.max_iterations` now flows into the run's real
budget (was: a post-hoc judge check only — a runaway case burned the whole
wall-clock allowance before failing). 0/absent still means the loop
default. A run capped at the limit still gets its one `final_synthesis`
turn to deliver what it gathered, so "right answer, over-verified"
survives while "gathered nothing" still fails honestly. The post-hoc
per-turn check stays as belt-and-braces and tolerates the one extra tick
an enforced stop records.

Note: this changes eval semantics — caps are contracts now. Trend
comparisons against historical rows for capped cases shift slightly, in
the more-honest direction.

## CLM state-file experiment: measured and parked

`agent.state_file` (from v1.17.x, default off) got its live A/B: 8 cases ×
3 reps per arm via the new `scripts/eval-ab.sh` driver. Result: **no
pass-rate benefit** (19/24 on vs 21/24 off — every difference was a known
flake that hit both arms) for **+30% tokens and ~2× wall time** (state.md
upkeep costs fs.write iterations every turn). Same shape as the route
bench: the mechanism is sound, our small brains don't convert it. The code
stays behind the default-off flag; full numbers in
`docs/clm-bakeoff.md`. The evolvable-instructions overlay
(`agent.state_file.instructions`) remains the cheapest lever to revisit
with a stronger brain.

## `scripts/eval-ab.sh` — reusable two-arm flag A/B driver

Fires a case list N times per arm against the live admin API, edits the
live `runtime.yaml` and restarts jaynet-web between arms, restores the
flag, and writes per-suite JSON plus a summary table. Crash-safe
continuation via `ARMS`/`REP_START`/`OUT_DIR`. Built for the state_file
A/B, kept for future flag decisions — measuring beats guessing.

## Upgrade

Pull, restart `jaynet-web`. `agent.anchor.budget` defaults on — no config
change needed; set it `false` to opt out. `loop_guard.jspace_badge_gate`
defaults on; j-space runs now must badge before editing project files.
Eval cases with declared `expect.max_iterations` will now actually be
capped (with the final-synthesis rescue), so expect capped-case rows to
look different from historical ones.
