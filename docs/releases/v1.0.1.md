**Post-release audit round-trip.** v1.0.0 got a full bug & security audit (web layer, tools surface, runtime correctness, frontend, deployment) — 1.0.1 fixes it end to end: all four A-findings, 14 of 17 nits, 9 of 16 suggestions in code (two more documented as accepted risks). Everything else is deferred as a product decision. Suite: 1163 tests, ruff clean.

The short version for upgraders: pull, restart, done — no config or data migration needed. Two things to glance at:

- The systemd units gained `NoNewPrivileges` / `PrivateTmp` / `ProtectSystem=full` — watch the first restart of `jaynet-web` (model servers run as children of that unit).
- If you run `quickstart.sh` fresh, llama.cpp is now pinned and sha256-verified instead of "latest, unverified" — `--latest` opts back into floating.

Highlights of the fix set:

- **Cloud/privacy gates closed everywhere** — `verify.*` and slash-command spawns could send content to a cloud model without approval or a privacy-taint refusal; both now gate exactly like `llm.call`.
- **Secrets hygiene** — model servers get a scrubbed environment, secret-bearing files no longer depend on the launcher's umask, `scrub_env` covers DSNs/passphrases/PATs.
- **Supply chain** — pinned, digest-verified llama.cpp in quickstart; pinned `requirements.lock` for the app itself.
- **Gate consistency** — `git.fetch` and the `all_owners` trace escape hatches require confirmation now.
- **Robustness** — a garbage-collectable scheduler task, an infinite process-restart path, non-atomic state writes and an unbounded login-throttle map all closed.
