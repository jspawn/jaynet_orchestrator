# JayNet v1.42.0 — Saber, eval allowlists and safe model swaps

This minor release adds an opt-in Saber ROCm backend, run-local model
restrictions for benchmarks, and a more reliable specialist swap lifecycle.
It also includes deterministic skill gates, new routing strengths and several
evidence/documentation improvements.

## Saber ROCm backend

- `scripts/build_tools.sh saber rocm` builds a pinned Saber revision for
  Qwen3.8-27B on R9700/gfx1201 and installs a versioned prefix with a stable
  `saber.rocm` link.
- TP1 and TP2 reference presets cover one- and two-GPU packs. Packs are
  pre-sharded and not interchangeable; downloads are always explicit.
- JayNet attaches to Saber's detached container, propagates its exit status,
  and stops only the preset's own container on shutdown or SIGTERM.
- The admin catalog, launch validation, resource reporting and model docs
  understand the `saber` binary type. Loopback binding is the default.

## Eval model allowlists

- Benchmark variants accept `allowed_presets` (comma-separated in the UI).
  Empty or omitted keeps every model available.
- Naming only the current brain blocks specialist routing, model swaps,
  spawned children, direct `model.use`, and explicit LLM calls to other local
  or cloud models. The allowlist is run-local and never edits the catalog.
- Active presets and presets currently assigned to a slot are selectable,
  including an archived preset that is still the live brain.

## Reliable specialist swap-back

- Slow `starting` responses are polled through route confirmation and a real
  generation probe instead of triggering an early fallback.
- Eviction records survive slow starts and post-eviction launch failures.
- Failed swaps restore the brain before any fallback child can spawn; failed
  restoration prevents the child from running at all.
- Successful children restore the evicted brain before the parent continues.
- The planner covers two-GPU brains, same-card one-GPU swaps and CPU-only
  systems. Unmeasured CPU RAM now fails conservatively rather than loading two
  large models together.

## Routing, evidence and documentation

- Deterministic auto-gates cover architect, codebase review, debugging,
  diff review, deep research and presentation workflows.
- New `visual-web` and `dom-analysis` strengths route browser/DOM work.
- vLLM and radiance update watchers appear only when their engines are
  installed/active. Delegate activity shows model and trigger labels.
- Ledger proof flags are invalidated by later edits. Research watch items have
  a separate watchlist, TinyBrainBot has a preset, and Occamy sizing is fixed.
- TDD and XLSX procedure guidance is clearer; `AGENTS.md` documents the eval
  allowlist and swap lifecycle.

## Verification

Saber landed with 214 targeted backend/admin tests plus dry-run validation.
The eval/swap changes passed 50 eval-route tests, 366 loop/coding/eval-harness
tests, 84 routing/spawn/model-catalog tests and a final 18 strength-routing
regressions. Ruff, mypy, complexity, documentation, JavaScript and diff checks
pass. Physical Q8↔Qwen swap testing and Saber's first GPU boot remain explicit
post-deploy steps.

## Upgrading

Pull and restart JayNet. No database migration is required. Saber remains
opt-in: build it, download the TP-specific packs, register the binary and only
then assign a Saber preset. Existing model slots and benchmark defaults are
unchanged.
