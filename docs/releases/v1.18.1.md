# v1.18.1 — 2026-10-05

Patch release: delegated tasks that legitimately edit a test no longer die
at the verify gate.

## `specialist.delegate allow_test_edits` — caller-declared tamper exceptions

Live traces showed delegations dying as "verifier stuck on the same
failure 2× (not converging)" — recurring across j-space-loop runs, passing
ones included. Root cause: the task itself *required* a test edit ("adjust
the test so it checks the new name"), the specialist edited
`test_service.py` exactly as instructed, and the verify gate's tamper
protection killed the run. The guard is correct for every undeclared case
— the `code-weakened-test` eval case depends on it — it just had no way to
know this edit was legitimate.

Now the calling brain can declare it: `allow_test_edits` takes the
relative test/check paths the task legitimately modifies. The declaration
lands as `verify.unprotect` on both the explicit-verify and the
`auto_verify` path and is dropped from both sides of the tamper comparison
— a declared file may be modified while every unlisted protected file
keeps full protection, and the exit-code and vacuous-pass checks still
apply. The arg never appears in the child's toolset (a compromised or lazy
specialist can't self-exempt), and a mis-shaped value is ignored, never
widens.

## Upgrade

Pull, restart `jaynet-web`. No config change. Brains learn the arg from
the tool description; tasks that don't touch tests are unaffected.
