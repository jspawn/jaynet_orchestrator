# JayNet v1.43.0 — oauthlib security update

This minor release updates one vulnerable LiteLLM dependency and records
compatibility with the latest h5i and jevify releases. There are no JayNet API
or adapter changes.

## Dependency security

- `oauthlib` moves from `4.0.0` to `4.0.1` in `requirements-litellm.lock`.
- This fixes CVE-2026-49272: the RFC 8628 device workflow could accept a
  missing or invalid device code and issue a bearer token without completed
  device authorization.
- LiteLLM remains at the tested `1.102.2` pin. The main and tools lockfiles
  are unchanged; all three pass `pip-audit` after the patch.

## h5i and jevify compatibility

- h5i `0.5.4` changes app/Postgres/embedded/proof components, not the browser,
  recon, websec or test CLI surfaces used by JayNet.
- jevify `0.3.0` adds TensorFold chat/image readout support without changing
  the serve/probe CLI, recipe schema or `/v1/systemone` contract.
- The existing adapters therefore need no changes. All 78 focused h5i, jev
  and update-check tests pass.

## Upgrading

Pull this release, synchronize the LiteLLM environment, then restart both
services so the proxy picks up oauthlib and JayNet reloads managed sidecars:

```bash
uv pip install --python litellmenv/bin/python -r requirements-litellm.lock
systemctl --user restart litellm-proxy jaynet-web
```

If h5i or jevify is installed, upgrade them separately with their installers.
No database migration or runtime configuration change is required.
