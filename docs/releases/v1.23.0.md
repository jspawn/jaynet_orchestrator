# v1.23.0 — new reference brain, capability tier, audit ledger cleared

Minor release on 1.22.0. Occamy 1.0 takes the brain crown from
Cyber-Tiel, tools gain a declared admin tier with a CI sweep behind it,
and every Tier-1/Tier-2 item from the 2026-10-11 audit list is either
fixed or explicitly deferred. No config migration. 2,334 tests green;
all gates clean; the complexity baseline shrank 19 → 15 — all four
grandfathered hotspots are gone.

## New reference brain: occamy 1.0

Occamy (Qwen3.6-35B-A3B co-work SFT, MTP draft head) was measured against
the incumbent on the 10-case flip set that actually distinguishes brains:
**20/30 vs cyber-tiel's ~18/30**, with a 74/93 (80%) full delta — and it
solves `graph-orientation` without delegation, a case cyber-tiel never
passed. Two builds tied within noise (the abliterated MiniPlus custom
quant at 20/30, the official-weights Q4_K_M at 18/30); MiniPlus is the
reference preset (`presets/brain-occamy-1-0.conf`), Q4_K_M ships as the
official-weights alternate. The launcher learned `MTP_MODEL` for
checkpoints that ship the MTP draft as a separate file. Full three-way
table and failure analysis: `docs/brain-bakeoff.md`.

## Capability tier: tools declare `admin_only`

The admin boundary used to live entirely in the name-pattern list
`security.admin_only_tools`. Now each lifecycle tool declares
`admin_only = True` on its class (`ops.run`, `job.*`, `serve.*`,
`model.use`, `model.measure`, `git.push`, `mcp.call`, `schedule.add`,
`test.run`, `code.deps`), and the declaration is enforced at selection,
dispatch and slash even when no config pattern names the tool — the
config list stays as the operator's way to restrict MORE. A completeness
sweep (`tests/test_tool_tiers.py`) fails CI for any tool that spawns host
processes or drives `ServeStart`/`ModelUse`/`JobStart` without the tier
or a justified written exception — the `procedure.save`-shaped gap from
last round now can't ship.

## Audit 2026-10-11 fixes

- **Red→green baseline is the tree at spawn time.** The authored-check
  baseline used `HEAD`, crediting pre-existing uncommitted work to the
  specialist (and agents rarely commit between steps). Now a temp-index
  snapshot (`add -A`/`write-tree`/`commit-tree`) captures the real "before"
  state; a baseline failing on a missing import/file reads as
  "unverifiable" instead of a fake red.
- **`trace.mine` owner pivot closed.** `all_owners=true` + an explicit
  `owner=` bypassed the admin refusal — fixed, with a regression test.
- **`eval.invalid_on_fallback`** defaults True in code, matching the
  shipped config.
- **OSINT scope rule** in the REDCELL worker prompt: organisations,
  infrastructure, threat intel, public figures in their public role —
  profiling or locating private individuals is declined.

## Hotspots: all four under the ceiling

`validate_case_dict` is a pydantic model stack (error wording remapped
1:1 — and the conversion surfaced a real bug: `EXPECT_KEYS` lacked
`canary_not_in_tool_args`, so both shipped injection eval cases were
silently skipped at load; they load again). `BrowserWebsec._argv` is
table-driven. `eval_runner.run_case` is a 4-phase pipeline,
`SpecialistDelegate.execute` a 12-phase one — both behavior-preserving
(AST-verified: zero lost strings or call targets). Complexity baseline
19 → 15. **Note for deploys:** the delegate phases are the verification
path — run one live delta after restart.
