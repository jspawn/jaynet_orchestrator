API tokens

For native clients like the voice app. A token authenticates as you — your usage, budget, and tool access all apply. It's shown once, so store it safely; revoke any token any time without affecting the others.

Using a token

Send it as a bearer token — works on every /api/* endpoint, with your account's rights (admin endpoints only if you're an admin):

curl -H "Authorization: Bearer jn_…" \ https://<host>:8071/api/health

Endpoints a native/CLI client typically needs:

EndpointWhat it does
POST /api/chat start a run: {"message": "…"} → {"run_id": "…"}
GET /api/stream/{run_id} SSE feed of the run: tool calls, tokens, the final answer
POST /api/approve/{run_id} answer a confirmation prompt: {"confirmation_id", "approved"}
POST /api/answer/{run_id} answer an ask.user question: {"ask_id", "answers"}
POST /api/cancel/{run_id} stop a running run
POST /api/voice voice-style turn: {"text": "…"} → short spoken-style answer; pass the returned conversation_id to continue; "stream": true returns a run_id for the SSE feed instead
GET /api/health liveness check (no auth needed)
GET /api/tools the tool catalog

Note: ORCH_WEB_TOKEN (from the server's env file) is a different, global admin token for automation — don't use it from client apps; a per-user token above is revocable and scoped to you.

Sessions

Signed in on a shared or lost device? Sign out everywhere. Your current session stays active; all others (and anything holding an old cookie) are invalidated. Changing your password does this automatically.
