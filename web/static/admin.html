Managed processes
      
    

    

      Brain, embedding, and reranker processes. Logs auto-refresh every 3 seconds when viewing.

    

  

  

    
GPUs

    

      The cards presets can be placed on — any count, mixed vendors/VRAM.
      id is the device index passed to HIP/CUDA_VISIBLE_DEVICES;
      label + VRAM are display hints only. A card can only be removed when no
      preset uses it.

    

    

      
      
      
    

  

  

    
llama-server binaries

    

      Named builds a preset can launch with. device_env is the variable used to pin
      cards: HIP_VISIBLE_DEVICES (ROCm), CUDA_VISIBLE_DEVICES
      (NVIDIA), GGML_VK_VISIBLE_DEVICES (Vulkan). A preset without a binary
      uses the launcher default (LLAMA_BIN).

      One process = one backend: a ROCm/CUDA binary only sees its own vendor's cards.
      To split one model across mixed-vendor GPUs, build llama.cpp with Vulkan and
      point that preset at the Vulkan binary. A binary can only be removed when no
      preset uses it.

    

    

      
      
      
    

  

  


  

  

    
Download from HuggingFace

    

      Pull a GGUF straight into the models dir — the GUI twin of
      scripts/pull-model. Enter a repo id like
      bartowski/Qwen2.5-7B-Instruct-GGUF, pick a file, download,
      then create a preset from the finished download.

    

      

    

    

    
  

  

    
Preset catalog
      

    

      One row per servable model. Local entries are rendered into the generated
      proxy config automatically. Conf edits apply on the next launch.

      Device decides where the model lives: one GPU, all GPUs (layer-split — e.g. a
      big brain using all VRAM), or CPU. Two models may share one GPU if their combined
      VRAM fits. To run without a specialist, set its device to CPU or stop it in the
      Processes tab. A remote preset adopts a server that is already running —
      llama-server, vLLM or Ollama on another box, or a reverse-proxied URL.
      JayNet treats it as local (slots, boot, model.use) but never launches or stops it.

Boot model slots
      

    

      Which preset each managed process boots by default. Takes effect on the next
      process (re)start — relaunch it from the Processes tab. Set a slot to
      (none) to run without it (e.g. no specialist, no RAG servers); an empty
      specialist falls back to the brain. specialist2/3 are optional extra
      specialists (aliases local-specialist2/3) — empty by default.

Default run budget
      
      

    

      Ceilings applied to every run that doesn't set its own. Toggle off =
      unlimited; enabling an empty field prefills a sane default. Per-run
      controls and per-user account defaults still layer on top (they can only
      tighten). Saved instantly and persisted.

Eval cases
      
      

    

      Behavioural test cases played through the real agent loop and graded by a judge
      model. Custom cases live in the data dir and layer over the built-in seeds — on an
      id clash the custom one wins; built-ins are read-only here (duplicate one to
      customize it). Export/import travels as .jaypack via the Studio tab.

Run

    

      Runs play cases through the live agent loop (unattended toolset) and grade them
      with the judge model — they cost real money, capped by the eval config. One suite
      at a time. Judge and driver models are configured in Config → eval.judge_model /
      eval.driver_model (fallback: local-specialist).

    

      
      
      
      
      
    

    

    

  


  

    
Scheduled runs

    

      Unattended recurring suites (e.g. a nightly tag run) — they fire through the
      same suite path and land in the results ledger tagged with the JayNet version,
      so a regression after a release or brain swap becomes a number. Skipped while
      any suite is running; a schedule whose case/tag disappears is disabled.

Backup

    

      Download a .tar.gz of the data stores (users, chats, presets, trace,
      memory, RAG, wiki, uploads, projects, customizations). Databases are snapshotted
      consistently — safe to take while the service is running. Keep the file private:
      it contains all user data.

    

      
      
    

  

  

    
Restore

    

      Replace the current data with a backup archive. This overwrites all current
      data and requires a service restart afterwards to take effect.

    

      
      
      
    

  

  


  

  

    
Plugins
      

    

      Optional capability bundles. builtin plugins ship with JayNet (off by default —
      they usually need extra pip packages); installed plugins live in the data dir's
      plugins/ folder (on by default). Toggling persists, but plugins load at
      startup: restart the service after a change. An unavailable plugin lists
      the pip packages it's missing. Plugins are admin-installed code running with full
      trust — only install code you audited.
